# Role-relative acquisition and transport onset

## Identity and research hypothesis

Policy: `acquire_transport__h01`; skill: `acquire_transport`; original heuristic index: 1; experiment: M1_v2. The assigned heuristic is **role-relative object-goal binding**: acquisition should depend primarily on relationships among the requested block, its predecessor, TCP and their own goals, using shared object encoders rather than separate color-specific motion programs. Its proposed benefit is improved occurrence-level sample efficiency and fewer wrong-object actions. That benefit is a hypothesis, not a result of this implementation session. The original heuristic is not modified by this document; the following describes the executable adaptation and its limits.

The policy is a learned action diffusion model over the FULL expanded acquisition slices. The repository retains all 24 assigned slices from 12 trajectories, including the shared transitions. No data are cropped into isolated pickup phases, and no source timestep, occurrence index, replay trajectory, scripted action sequence, or termination controller is used. For example, demo10000 contributes [0,185) and [265,585), not merely its two closure events.

## Important interface adaptation: roles are learned, not supplied

The original proposal asks a caller for stable requested-object and predecessor IDs. The actual numerical forward interface only accepts noisy actions, diffusion timestep, and two 47-dimensional raw observations. Neither the observation schema nor the training batch has role-ID fields. We cannot implement an externally selectable role binding without changing that interface. Instead, this implementation learns **soft requested and predecessor roles from the causal scene**, and explicitly restricts applicability to the demonstrated red-then-blue order. It does not pretend to honor an arbitrary external ID. An inference caller may track the requested name for handoff, but that name is not an extra input to this model.

During training only, a contemporaneous scene-derived teacher assigns blue/requested and red/predecessor when the red cube's rotated footprint fits inside its own goal pad in XY; otherwise it assigns red/requested and no predecessor. This teacher ignores height on purpose: in the recurrent entry red is over its pad but remains held well above the surface. It identifies the occurrence, NOT which object must move immediately. The action denoiser still learns to finish red lowering and release before going to blue. On the inspected source slices these labels are well separated: early red is about 0.23-0.24 m from its goal in X, whereas recurrent red is within a few millimetres of the goal XY. This is a dataset-supported pseudo-label, not a general task-order solver. All-range boundary summaries and additional inspections support the same geometry, but there has been no policy-success evaluation or exhaustive label audit.

At deployment there is no threshold switch in the action path: shared graph features produce a two-way requested distribution and a three-way predecessor distribution (two objects plus null), and both are soft conditioning inputs. They are recomputed at each observation, not stored as contact or phase memory. Lack of caller binding can produce unstable or incorrect nominations off distribution, especially if an earlier red grasp failed or an unexpected object is on a goal. A stable externally specified role would require a future interface extension, not an undocumented side channel. The current implementation must not be selected for reversed order or a contrary object request.

## Observation representation and normalization

The causal inputs are the provided two successive observations: qpos [0:9], qvel [9:18], world TCP pose [18:25], red pose [25:32], blue pose [32:39], red goal [41:44], blue goal [44:47]. Pose quaternions are wxyz; translations and goals are metres; arm coordinates are radians; measured fingers are metres. Drawer compatibility zeros are unused. No camera input, future state, demonstration clock, previous commanded action, privileged contact flag, or hidden event label is consumed by forward.

All normalization is derived from the supplied complete-original-training-demonstration normalizer, identifier `8c2a48fbe12c5ca231497f52e582c40a2bd0f2f1dda8ba9c04cf18addd467306`. Nothing is fit to an acquisition slice. Robot positions and velocities use the supplied channel midpoints and half ranges. The same spatial scale for BOTH object nodes and translation edges is the coordinatewise maximum of the supplied TCP, red-position and blue-position half ranges. This avoids giving red/blue narrowly different Y scales. Absolute object positions and goals are centered by the supplied TCP midpoint, preserving their base/world locations, not replacing them by relative-only state. These choices are fixed algebraic transformations of the common normalizer, not a refit. There is no observation clipping. Actions keep the repository's shared affine action encoding and fixed DDPM decode/clipping; no custom Cartesian actions or residual servo are introduced.

Each object snapshot has 34 features: absolute position (3), its own absolute goal (3), goal-minus-object edge (3), object-minus-TCP edge in world axes (3), world rotation matrix (9), TCP-relative rotation matrix (9), signed task-containment margins (3), and first/second task-order tag (1). The goal is bound to the node before any pooling. XY margins subtract the world X/Y extents of the rotated 0.04 m cube from the 0.06 m pad half widths and then subtract center error. The vertical margin is 0.011 m minus absolute object-goal Z error. These are observed geometry features, not differentiable action constraints, contact proofs, or standalone penalty losses. Extents include all three cube axes for full projected XY containment. Gravity is explicitly retained in the robot features as world (0,0,-1).

Object features combine current, previous and current-minus-previous snapshots into 102 channels per node. The robot feature similarly combines 33 channels per observation (18 normalized qpos/qvel, 3 normalized TCP coordinates, 9 world rotation entries, 3 gravity components) into 99 channels. Differences are displacement or feature change per observation interval; no unspecified timestep is used to claim metric object velocities. qvel is additionally observed directly. A duplicated initial history therefore has zero differences, without needing special phase initialization.

Quaternion normalization and conversion to rotation matrices make the represented orientations invariant to quaternion sign. Relative rotations do not remove the retained absolute world rotation or the fixed gravity/base frame. Matrix representation and relative translation edges do not make joint targets SE(3)-equivariant.

## Learned architecture

1. One shared MLP (102 -> 192 -> 192, SiLU, final LayerNorm) encodes both object histories. It has no color-specific weights. A separate robot MLP (99 -> 192 -> 192) encodes robot history.
2. Two fully connected, pre-normalized graph-attention blocks operate on the robot and two object nodes. Each has four heads, width 192, residual attention, and a SiLU feed-forward network of width 768. Geometry edges are already features of the nodes. Attention between the objects supplies scene context; this is not an explicit collision graph.
3. Shared object heads predict requested and predecessor logits; a robot head predicts the null-predecessor logit. Soft role probabilities are fused into both object nodes by a shared 194 -> 192 -> 192 MLP, followed by one further graph-attention block.
4. Conditioning concatenates the updated robot node, requested-weighted pool, predecessor-weighted pool including a learned null vector, symmetric object mean, null-predecessor probability, and the 99 direct robot-history features. A projection 868 -> 384 -> 256 conditions the diffusion backbone. The mean pool and unrestricted robot attention ensure that selecting blue never deletes held red from the representation.
5. The supplied temporal conditional U-Net uses widths [128,256,512], 128-dimensional diffusion-step embedding, kernel 5, eight groups, and FiLM scale/bias conditioning. It predicts epsilon for a normalized [16,8] action chunk, not a deterministic waypoint or phase controller. Its output goes through the fixed repository DDPM sampler and action decoding.

There are no object-array positional embeddings in the graph. During training, each example independently swaps its internal two object tokens with probability 0.5. All pose, goal, role-relevant order tag and temporal features travel together. Shared heads, graph attention and symmetric/role-weighted pooling make this internal reordering structurally invariant up to numerical roundoff. No action or joint coordinate is reflected. Named raw red/blue fields still carry their semantics and first/second tags: swapping those externally while leaving the nomination/order convention inconsistent is NOT the same operation. The tag acknowledges the established task order rather than asserting color-free global symmetry.

## Losses and gradient paths

Let epsilon_hat be the forward prediction, epsilon the supplied DDPM noise, and m the action padding mask. The diffusion loss is sum(m * (epsilon_hat - epsilon)^2) / max(8 * sum(m), 1). The prior loss is half the sum of requested-role and predecessor-role categorical cross entropies. Total loss is:

`L = L_epsilon + 0.1 * L_role`.

The role labels are constructed under no_grad from the current observed red pose/goal, but the cross entropies are evaluated on TRAINABLE predictions. They therefore train the shared object/robot encoders, scene attention and role heads. The diffusion loss trains these same encoders and heads through soft role fusion and pooling, plus the final graph, conditioning projection, null vector and U-Net. There is no constant observed-only loss. Role supervision uses a second canonical-order pass through the shared scene encoder, so labels never get detached from their semantic node by augmentation. No parameters or hard teacher roles are copied into deployment action outputs.

No future-state auxiliary, learned forward dynamics, contact-phase classifier, IK, analytic FK, gripper constraint, velocity penalty, or waypoint hierarchy is implemented. `future_obs` and `future_mask` are unused. All action padding uses the repository mask, including the t-1 through t+14 action alignment and slice-end padding. Forward only sees causal history. The fixed recipe is seed 0, 20,000 updates, batch 128, AdamW 1e-4 with weight decay 1e-6, 500-update warmup plus cosine decay, gradient norm cap 1, EMA 0.999, 100 DDPM training/inference steps, horizon 16, and execution prefix 8. Model selection is the last EMA at the declared budget, not an outcome-selected checkpoint.

## Why the full overlap is learnable from causal state

Directly inspected evidence includes demo10000/0,80,100,110,150,170,184,265,300,350,400,424,470,504,506,550,570,584; demo10003/0,76,105,166,180,255,290,335,408,455,495,558,570; and demo10011/84,116,191,272,309,434,480,520,560,583. These are source indices inside the assigned slices, not model inputs or a switch schedule.

At demo10000/265, red is at approximately (-0.174,-0.245,0.208) m, TCP at (-0.184,-0.245,0.209) m, both fingers near 0.0183 m, and the demonstrated command remains -1. At demo10003/255 this predecessor is around z=0.246 m; demo10011/272 is around z=0.126 m. The measured all-trajectory recurrent entry support extends roughly to z=0.253 m. This is not an idle arm from which to drive straight to blue. Goal-aligned red pose, small TCP-red offset, measured aperture, arm qvel and short-history co-motion distinguish it from an already released predecessor. Requested blue stays on the source table. Both objects, both goals and robot features are retained.

At demo10003/290 the red object is near z=0.0227 m but measured fingers are still about 0.0183 m while the action begins opening. At demo10000/300 the measured fingers have opened to about 0.0371 m, the red object is at z=0.0200 m and TCP remains low near z=0.0229 m. At demo10011/309 the fingers are about 0.0400 m with TCP still low. Goal containment alone therefore does not imply that the transition is over. Subsequent open-finger rise (demo10003/335 and demo10000/350) leaves red at its pad, followed by lateral movement toward blue (demo10000/400,424). This entire lowering/opening/retreat/reach sequence is included in supervised diffusion training, not handled by a separate controller.

The following delivery overlap also includes low, still-open approach, closure, lift and first transport motion. Demo10000/100 is open near red at table height with roughly -9.5 mm TCP-minus-object world X offset; /110 is measured closed. For blue, /504 is still measured open while command becomes -1, /506 has closed fingers, /550 is lifted to around 0.217 m, and /570 and /584 are near z=0.280-0.281 m with preserved TCP-object offset and the onset of horizontal motion. Other trajectories show the same pattern without identical source event times. qpos/qvel, both poses/goals and their differences can identify these geometries partway through a transition. Identical dwell states can remain temporally ambiguous: diffusion learns the demonstrated action distribution rather than consulting a clock, and reliable termination timing is not guaranteed.

## Invocation and handoff guidance

The inference API chooses this skill and duration; the model contains no scheduler. Initial entry is supported from the demonstrated home posture, open fingers near 0.04 m each and TCP z about 0.442 m, with both blocks on the table. Recurrent entry includes requested blue on the table with held predecessor red aligned over its pad, as above. Entry is also supported within shared approach, closing and partially lifted states, subject to the observed geometry and supported order.

Continue while predecessor lowering/opening/retreat or requested acquisition remains incomplete. Usual elevated transfer support is requested object and TCP near z=0.279-0.282 m, measured fingers roughly 0.01824-0.01830 m each (total width near 0.03653 m), preserved relative pose, and incipient motion toward that object's goal. The successful demonstrations continue -1 gripper commands. A held object should move with TCP; width alone, an arm-only rise, or a single goal/height test is insufficient to infer acquisition. Proposed broader readiness bands such as z=0.25-0.31 m or fingers 0.015-0.025 m per finger are not calibrated and are not executable gates here.

The delivery successor may start earlier within the shared pickup overlap if it can finish acquisition, or take the usual elevated transfer without resetting posture/velocity. Supply the same requested object name in the external orchestration, its own goal, both object world poses and live TCP, qpos/qvel and causal history. This model passes no recurrent contact state or latent role cache. Do not infer that its requested role means the predecessor has already disengaged. `HANDOFF.json` provides the corresponding API guidance and failure cues.

## Applicability, success, limitations and scientific claims

Applicability is limited to the demonstrated tabletop, Panda base/kinematics/joint order, top-down orientation family, fixed world gravity, separate fixed pads, small source-position jitter, and established red-first order. Both objects and goals must be observed. There is no learned visual encoder. Dependency is Torch plus the repository's `appl.public` diffusion backbone and masked epsilon helper; no files, network, external IK or external controller are accessed by policy code.

The task completion contract, not this handoff guidance, defines success: both rotated block footprints must be contained in their respective pads, with object center Z within 0.011 m of the supplied target heights. There is no extra required gripper release, TCP clearance, speed limit or sustained hold. The trained transition includes release because it appears in the data and is useful for reaching the next acquisition, not because release redefines task success.

All geometric observations are evidence rather than contact sensing. The successful-only dataset cannot establish recovery from a missed grasp, slip, wrong predecessor or stale external nomination. Goal relocation, arbitrary base rotation, new obstacles, and color/order reversal remain untested. Representation sharing does not imply joint-space reflection, physical translation invariance or safe action constraints. Quaternion-sign and internal-token-order invariance are the limited representational properties actually implemented. No empirical performance advantage, contact guarantee or calibrated transfer detector is claimed. Suitable future tests would compare a parameter-matched flat-encoder diffusion model, remove absolute robot/world features, remove role supervision, and measure held-out-trajectory and occurrence-level sample efficiency; none is reported as completed here.
