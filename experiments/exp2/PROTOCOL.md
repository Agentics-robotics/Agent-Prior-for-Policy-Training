# APPL Exp2：重建协议与当前执行边界

执行规范为根目录 `APPL_EXP2_REBUILD_AND_EXECUTE.md`。本文件区分已运行的开发诊断和被门槛保护的正式流程；研究假设尚未得到验证。结果由 `exp2 report` 集中生成，不能用接口通过代替任务成功。

## 数据、环境与固定接口

复用 15 条原始完整 ManiSkill 示范：demo1000–1011 为 **12 条训练**，demo1012–1014 为 **3 条验证**。共 16006 个动作、16021 个观测。完整轨迹是独立示范计数单位，技能片段不增加示范数。默认只训练原始示范；MuJoCo 和独立参考控制器 rollout 不自动加入训练。

ManiSkill 的 `APPLDrawerExchange-v2` 是示范来源与最终目标平台。MuJoCo 是 API 依据允许的机器人资料和训练示范校准的开发环境。viser 只显示已记录的状态、场景、机器人及轨迹，没有控制权。真机尚未接入，不能把 Panda 仿真动作定义当作已确认的真机控制契约。

| 字段 | 扁平索引 | 单位/约定 |
|---|---|---|
| qpos | 0:9 | 七关节 rad，两个手指 m |
| qvel | 9:18 | 对应 rad/s、m/s |
| tcp_pose | 18:25 | 世界位置 m + wxyz 单位四元数 |
| red_pose / blue_pose | 25:32 / 32:39 | 世界位置 m + wxyz |
| drawer_position / velocity | 39 / 40 | m / m/s，开启方向世界 -x |
| red_goal / blue_goal | 41:44 / 44:47 | 世界目标 m；蓝目标随抽屉平移 |

原生 `pd_joint_pos` 动作是 7 个绝对关节目标（rad）+ 1 个夹爪命令。夹爪 [-1,1] 对应每指 [-0.01,0.04] m，正号张开。机械臂不额外归一化成原生 [-1,1]；训练动作 affine normalization 只执行一次，部署逆变换一次。所有方法使用相同物理 actuator bounds 饱和。控制 20 Hz、物理 500 Hz，每控制动作 25 个物理子步。

训练窗口以执行 action[t] 之前的 observation[t] 为当前状态，历史为 [t-1,t]，预测 action[t-1:t+15]，在线从索引 1 开始执行 8 步（0.4 s）。首尾 padding 不跨 episode，越界动作被 loss mask 遮蔽。统计仅拟合训练片段；不裁剪 OOD 观测。

## 训练与诊断

固定共同主干是 Conditional U-Net 128/256/512，时间嵌入 128，kernel 5，GroupNorm 8。完整 DP 为 16,998,408 个参数。DDPM 100 步 cosine/epsilon 训练，DDIM 16 步推理，clip_sample=false；AdamW lr=1e-4、weight_decay=1e-6，batch=128，EMA=0.999。

| 阶段 | 预先设定的操作 |
|---|---|
| D0 | demo1000、1007、1014 原始 seed/reset 完整动作重放 |
| D1 | demo1000 多阶段固定 batch，5000 次真实更新；采样关节 RMSE <0.05 rad、夹爪 MAE <0.15 |
| D2 | demo1000 完整轨迹 30000 次更新，再从原始起点执行 |
| D2 sampler | 同一权重，只读比较 DDIM50/chunk8 与 DDIM50/chunk4；只用训练起点 |
| D2 quaternion | 同一数据、seed、预算；12 个四元数组件按物理 [-1,1] 范围归一化，其他统计不变；独立结果保留 |
| D3 | 单轨迹三技能各 30000 次更新，原始动作前缀到达技能起点；前缀不计为 learned-policy 成功 |
| D4 | 全部 12 条训练轨迹、30000 次更新；开发初态 seed6000–6019 共 20 个 |

D4 正式准入门槛在运行前固定为 **16/20 完整成功**。D2/D3 失败须完成诊断，不能只看 loss；D4 未达到门槛时不得扩展正式矩阵。当前针对 sampler 和姿态数值尺度的诊断不作为正式 checkpoint 搜索。

每次训练保存模型/EMA、optimizer、CPU/CUDA/NumPy/Python RNG、采样 generator、进度、训练配置及数据/源码 hash。最终采用预定预算末尾 EMA，不以最终 ID/OOD 结果挑 checkpoint。记录非零梯度、初末权重 hash/L2 差、实际步数、窗口/有效动作曝光量、训练计时和重载一致性。GPU 初始化的小型可信网络 warmup 单列在 enforcement.json，不算候选学习步数。

## 成功与交接

最终成功由固定评估器判断：抽屉 >0.26 m；红块完整 XY 占据在边长 0.12 m 的垫内、中心 z 在 (0.014,0.031) m；蓝块完整 XY 占据在抽屉内部半宽 [0.172,0.182] m、中心 z 在 (0.053,0.074) m。旋转后的立方体包围范围参与判定。

两物体线速度 <0.02 m/s、角速度 <0.2 rad/s；每个手指 >=0.035 m，TCP 到两个物体各 >=0.08 m；连续满足 10 个物理控制步（0.5 s）。技能交接还要求 TCP z >0.28 m。最终任务成功和技能完成是不同判定；没有附加松爪/稳定控制器，策略自己产生必要动作。API 等待和重复 observe 不增加物理时间。完整任务上限 1500 步，单次技能最多 600 步且受全局剩余步数限制。

`already_satisfied` 只表示零步观察式前置检查满足几何/释放；它不虚增稳定时间或最终成功。报告区分 API 从未调用已完成技能、调用后零步退出和不必要的实际动作。超时不等于完成。

## MuJoCo 校准与权限

重建 API 只能读公开 Panda URDF、固定契约、训练状态和同步图像，并通过 schema 化 XML edit/calibration 工具改其专属 model.xml。禁止插件、include、mocap、物体执行器、附着、穿越文件权限或目标环境调用；固定已知机器人关节/执行器、物体大小/质量和控制单位。API 自行修订指尖几何与摩擦/接触参数，开发 Codex 不替它调模型。

先于候选验证冻结校准标准：TCP RMSE <=1 cm，抽屉 <=1 cm，物体 <=2 cm，FK 最大位置误差 <1 mm；各案例还必须最终释放、稳定并完成全任务。2 cm 为 4 cm 立方体边长的一半，低于目标区剩余容差。固定案例来自 **两条训练轨迹**：demo1000/1007 完整重放，以及 demo1000 的 step340/700 中途起点；不是四条独立新轨迹。

中途复位没有原生接触 solver 快照；使用保存的 q/qvel，物体线速度由相邻观测估计，角速度置零。通过这组重放不证明整个 OOD 空间都已校准。校准成本和候选验证成本分开。校准结束后候选 API 无模型编辑权限，不能通过改物理使 policy 过关。

## API 工具与两版技能库

真实 provider 沿用现有本机 Responses 服务，模型 gpt-5.5、reasoning high、store=false；凭证仅在 API 客户端读取私有 0600 文件，不进入候选进程。保留 native function_call/function_call_output、完整响应、加密 reasoning continuation、调用 ID、源码内容对象和明确提交 hash。不自动重试传输失败；没有可靠响应的调用记为费用/结果不确定。

设计工具和严格 JSON schema 在 `src/appl/design.py`、`library.py`：read_public、read_trajectory、read_training_image、read_file、write_file、check_candidate、submit_candidate、train_candidate、status、verify_library、read_verification、freeze_library、finish_design。候选仅写自己的未提交平面 .py/.json/.md 文件，可以新增自有 helper 模块。固定接口为 build_model / condition / encode_action / decode_action / compute_loss。主对照保留同一 DP 主干，额外编码器不得超过主干参数的 10%；相对观测不自动使绝对关节输出等变，必须解释并检查动作编码的逆变换。

API 决定切分、各技能 prior、表示、loss 和小型条件/编码结构；不是预置 prior 菜单。允许每技能多个候选，最终至多保留 6 个 policy，覆盖三个固定任务子目标。基于性能修改必须显示为第二版，不能藏入接口修复。

1. API 自己写并提交第一版候选，完成完整真实训练。
2. 第一版完整库接受一次固定 MuJoCo suite：每 policy 两个训练片段起点、两个完整组合；第一次 suite 输出后进入修订阶段。
3. API 最多修订一次，可改切分/机制、保留或删除候选；新版本须真实重训。
4. 显式 freeze_library 固定第二版成员、顺序、代码、配置和说明；随后一次只读验证，拒绝任何再修改/重训/选择。
5. 外层冻结完整正式协议和目标初态，再训练其余配对 seed、最后执行目标 ID/OOD。

默认正式上限：120 次 API 请求、180 次工具、18 次接口检查、12 次候选训练尝试，恰好两次完整库 suite。接口检查包含 **2 次真实梯度更新**，不是 Exp1 的零更新检查；它单独记账，不增加正式模型槽位。当前能力试跑上限 50 次 API、候选 5000 次更新，明确不属于正式设计轮次。

候选在导入前安装 Landlock/seccomp，移除密钥与网络/进程创建权限；只读数值依赖、显式公共模块、自身代码及授权 checkpoint，写入独立作业目录。所有 GPU 进程经设备节点命名空间隔离并核对 UUID，只使用物理 4–7 卡。检查已实测越权文件/环境、socket、子进程被拒绝，限制后 CUDA optimizer 仍有实际权重更新。

## 方法与 ID/OOD

| 方法 | 匹配规则与差异 |
|---|---|
| M0 | 完整轨迹一个 DP，无高层调用；总参数量与多策略系统天然不同 |
| M1 | API 最终同切分、同每技能主干/噪声日程/数据/更新数/最终 EMA；删除 API 的数值 prior |
| M2 | API 实际生成的候选表示/loss/小型结构；与 M1 使用同高层 API prompt/schema、任务状态、适用条件文本及权限 |

部署 API 只在观察、技能调用/返回及结束处决策。一次 invoke_skill 在本地保持模型并执行低层闭环；不逐动作远程推理。M1/M2 共享 policy_id/角色/适用条件及调度机制，不给其中一个额外控制器。部署看不到另一方法的结果；最终结果不会进入设计会话。

坐标均为世界 m。ID 采样分布：红块 x∈[0.093,0.117]、y∈[-0.077,-0.053]，z=.063；蓝块 x∈[-.415,-.385]、y∈[.285,.315]，z=.02。已观测的 12 条训练支持范围另见 audit.json；分布范围和样本经验范围不可混淆。

OOD-position 固定红块 y +.03、蓝块 x +.05：红 y∈[-.047,-.023]、蓝 x∈[-.365,-.335]，两轴均超出训练支持；其他位置和目标不变。OOD-state 将蓝块初始放在抽屉局部 [-.065,.075,.028]，世界 [.125,.075,.063]，目标仍要求取出红块并保持蓝块在内。这只检查已完成子目标处理，不声称任意任务重排。

参考控制器已对每条件 seed8000/8001 各检查两个代表场景。它用于物理可达性，未筛除 learned-policy 失败、未加入示范。不能据此保证每个连续初态都可解。主矩阵计划 3 个训练 seed × 每条件 10 个配对 reset；总 270 个方法回合，是受资源约束的 pilot，不采用原建议的每条件 30 个 reset。正式目标 seed 由外层在 freeze.json 内持有，设计工具不可读取。

共享一次 API 设计、重复训练 3 个 seed 只测训练随机性，不能当作 3 次独立 Agent 设计。M1/M2 按技能匹配训练曝光，API 探索/重训、MuJoCo 校准/验证、推理/API 等待均额外记账。没有代理账单时不虚构美元费用。

## 恢复、归档与当前限制

已提交候选和 checkpoint 使用内容 hash；完整训练状态可从一致的 checkpoint 恢复，源码/数据/配置不符必须建立新运行。工具已经提交的结果按 call ID 复用；中断中的工具需依据可靠 receipt 显式对账，不能自动再次执行。物理 episode 未保存完整 solver snapshot 时，不允许拼接两次复位后的片段；新 attempt 要保留原中断记录。

共享 bug 只修一套源码，正式阶段统一重跑全部受影响方法/配对场景。真实策略失败保留。旧 Exp2 内容和 Exp1 数据/checkpoint 不参与无效产物清理。当前未启动正式三技能周期时，它仍是未经真实端到端验证的门槛后路径，不能称作正式实验完成。

资源：本试跑已有锁定 Menagerie Panda 资产、Apache-2.0 LICENSE、逐文件来源/hash，commit `8161bba264d7fa7c99ca301e91e7fb44737676ad`；ManiSkill 内置 Panda URDF 已实际使用。场景为公开工程几何，自采完整轨迹，不假定外部现成长程数据集可用。本次没有待人工认证/下载的资源阻塞。未来真机仍需实际型号、SDK/许可、原生动作与传感器同步、校准和复位接入，当前未实现也未验证。

补充工程核验：固定 CUDA 确定算子/CUBLAS/cuDNN 后，真实 GPU 的 4 步连续训练与 2+2 步恢复权重 hash 完全一致；新流程将可信 warmup 与候选初始化随机状态分离。旧未中断诊断保留其原始数值设置，不假称在新设置下重跑。GPU 启动器同时固定 Pixi C++ 运行库搜索路径，已实际检查 SAPIEN 之后导入 SQLite 和创建原生场景。
