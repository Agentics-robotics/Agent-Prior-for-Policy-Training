# Round 2 frozen experiment protocol

This is a **custom MetaWorld extension**, not the unchanged standard benchmark. The user specification is preserved in `ROUND2_SPEC.txt`. Round 1 data, checkpoints, code and results remain intact. Round 2 lives in `src/round2`, `configs/round2`, `data/round2`, `runs/round2`, `results/round2`, and `artifacts/round2`.

## Question and permitted conclusion

With 20 successful physical demonstrations per task, does an information-preserving cabinet-frame observation/action parameterization enlarge the range of cabinet yaw over which a diffusion policy succeeds? No positive finding is presumed. Simulator progress and contact are diagnostics, never policy inputs or training targets beyond the native action labels. Contact associations do not establish a causal mechanism. Fixed end-effector orientation breaks exact rotational symmetry of the complete robot/task system.

## Environment and calibration

MetaWorld commit `6e01ad7e2ffb2302e4dca04f796fcd8837df8540`, MuJoCo 3.3.0, and all original Pixi dependencies are retained. Only task entries were added to `pixi.toml`; the original configuration and lock are archived under `artifacts/round2/round1_archive`. The historic Round 1 whole-workspace fingerprint includes `pixi.toml`, so use its archived task configuration when reproducing that historical fingerprint. Existing Round 1 model/data/evaluation identities are not rewritten.

The stationary cabinet root is yaw-rotated around its base world Z axis. Robot, tabletop, gravity, cabinet dimensions, joints, control scale, fixed end-effector orientation and timing are native. Each episode compiles a fresh MjSpec from the original XML, with the requested root position and quaternion, ensuring static collision structures match the scene. Canonical native Task+seed reset then establishes robot integration state. Corrected history and goal are constructed after FK.

Calibration identified a genuine geometry bug in the naive extension: the stock rear retaining rail at world y=.99 penetrated the rotated closed drawer, causing spontaneous opening. That accessory rail is moved to world y=1.15 identically for both tasks and every yaw. Tabletop and robot remain unchanged. All earlier calibration records, including invalid apparent successes, remain in the ledger. See `docs/ROUND2_GEOMETRY.md`.

Joint endpoints come from finite native limits and opening sign: drawer closed=0/open=-.16 m; door closed=0/open=-2 rad. Progress is `(q-q_closed)/(q_open-q_closed)`. Goal handle position is FK at progress .80, computed in separate MjData. Success requires progress >=.75 for three consecutive control steps, with progress <=1.01; the 1% endpoint tolerance explicitly accommodates MuJoCo soft constraints, and larger violations cannot count. Calibration rejects any episode leaving [-.01,1.01]. Diagnostic reward is progress increment. Native door world-X success is bypassed. Maximum 500 steps, native dt=.0125 s, frame_skip=5, Cartesian scale=.01 m per normalized unit, 4D xyz+gripper control are retained.

Final expert: drawer uses the official feedback script in a canonical cabinet frame, with xyz gain multiplied by .2 after progress .35 to avoid overshooting the short native joint limit. Door uses three online geometric phases: approach above handle, descend, follow the current handle tangent. Its approach offset in the rotating door plane is [.01,.02,0] m; approach/descent gain 10, interaction offset [0,-.07,0] m and gain 25, closed gripper. Both experts use actual current feedback, never artificial rotated trajectories. See source for phase thresholds. Only actual WORLD actions after native component clipping are stored.

Calibration seeds are separate from data. The ledger counts every expert probe/revision. Per tier, pre-generated states include 36 balanced yaw/position cases, nine zero/train-boundary cases and twelve OOD interval-edge cases. Each receives 100 zero-action steps in addition to its expert rollout. Feasibility requires no known invalid state, >=90% overall expert success, >=80% at each OOD magnitude. **Both tasks pass tier A with 57/57 final checks:** train [-10,10] degrees; near +/-20, mid +/-35, far +/-50, with OOD jitter uniform [-2,2]. Drawer final expert is v5; door final expert is v6. Earlier failed revisions are superseded calibration evidence, not formal results. Angles were selected before any formal or debug policy scores.

## Data and information parity

New train20 per task is collected directly: four equal yaw bins, five successful episodes/bin, at most 100 attempts/bin. Only this train20 fits normalizer statistics. Dev20 and all six final splits of 20 states/task have independent base reset seeds. The split names are test_iid, test_position, test_yaw_near, test_yaw_mid, test_yaw_far, test_combined. Position OOD sides have ten each; signed yaw splits have ten each; combined has five per side/sign combination. No train/dev/test seed is reused. World/frame models share exact episode files, initial states and inference random seeds. All states are frozen before formal training; valid failures are retained.

Drawer train x=[-.04,.04], OOD x=[-.10,-.06] or [.06,.10], y=.9,z=0. Door train x=[.03,.07], OOD x=[0,.02] or [.08,.10], y=[.88,.92],z=.15. NPZ stores obs[T+1,41], actual actions[T,4], reward/flags/progress/contact diagnostics for demos, and full initial integration/model/goal/history snapshots. Eval NPZ stores full initial snapshots. All 40 full demos replay within 1e-6 (float32 storage); every eval snapshot resets within 1e-9. Hash manifests establish provenance.

Both methods receive corrected native current18+previous18+goal3, plus the same sin(yaw),cos(yaw): 41 dimensions. Real quaternions uniformly use XYZW with continuous sign; absent second-object slots remain zero. The frame method applies R.T to each hand-minus-its-own-handle vector and current goal-minus-current-handle vector, retains world handle coordinates, maps real object orientation by Q_frame=R.T Q_world, and retains scalar gripper/yaw metadata. The inverse reconstructs world information. No joint angle, progress, success, phase, timestep or future state is exposed.

Positions and ordinary scalars use train20 mean/population std, floor .001. Real quaternions and yaw sin/cos pass through unchanged; zero placeholders stay zero; no OOD clipping. WORLD action labels remain stored in [-1,1]. Frame training xyz targets are R.T times those actual actions and may exceed [-1,1]. Gripper is unchanged; no per-axis action normalization.

## Training and evaluation

Exactly four runs: `r2_drawer_world_n20_s0`, `r2_drawer_frame_n20_s0`, `r2_door_world_n20_s0`, `r2_door_frame_n20_s0`. The Round 1 U-Net, optimizer, EMA, masked loss, independent RNG streams and checkpoint restoration are reused unchanged; observation dimension becomes 41. The only diffusion output change is that both DDPM/DDIM have clip_sample=False and thresholding=False, and the final predicted clean chunk is not clamped. Decode the complete chunk into WORLD first, then apply native component clipping only to executed actions (including gripper). R is known from the current cabinet yaw and fixed across the chunk.

Float32, deterministic kernels, TF32 disabled, GPU 1, one formal training subprocess at a time. Two observations condition 16 actions a[t:t+16]; execute indices 0:4, repeat earliest history, zero/mask tail without crossing episodes. DDPM 100 cosine epsilon-prediction; DDIM 16 deterministic steps, eta=0. AdamW lr=.0001, wd=.000001, betas=(.9,.999), batch/microbatch=128, grad clip=1, EMA=.995; fixed 20,000 updates and checkpoints 5k,10k,20k. Seed0 model initialization, loader100, diffusion200. Paired initial weight hashes, parameter counts and sampling/noise/timestep digests must match. Every formal run starts fresh in a separate Pixi subprocess.

Exactly one 200-update smoke per configuration (800 actual debug updates maximum), interrupted at100 and resumed in a fresh process to verify model/EMA/optimizer/RNG restoration. Debug artifacts are never formal initialization. Source, protocol and data hashes freeze before formal training.

Each of twelve EMA checkpoints receives dev20 closed-loop rollouts. Selection maximizes dev successes, then minimizes mean first success among successes, then chooses earliest checkpoint. With no success select earliest. All four selections freeze together before any final test. Final evaluation is four models x six splits x20 =480 episodes. Exceptions remain failures in their denominator. Invalid joint events remain explicit diagnostics. Identical state and policy-noise seeds pair world/frame. Save actual action trajectories for deterministic video replay.

Primary metric is equal-weight near/mid/far yaw success (60 episodes/model); report each magnitude and sign as well. Secondary: IID, position, combined, first success, progress and clipping. Contact uses mapped actual gripper/handle collision geom pairs sampled each control step; it can miss transient contacts inside a physics substep and is distinct from distance. Failure labels are no_approach (minimum hand-handle distance >.08 m), approach_no_contact, contact_no_progress (maximum progress <.1), progress_not_completed. Successful rollouts form a separate label. Report all-episode cumulative success versus steps with failures unfinished at500; conditional successful-only mean times need not be comparable across different failure rates.

## Deliverables and accounting

Figures: split success, yaw magnitude/sign curves, progress/failure diagnostics, training/dev curves, cumulative success curves. Fixed videos choose each task/model's first IID and far-yaw success and failure if present, plus first paired world failure/frame success with both actual action replays; absence is explicit. Frame display is vertically flipped to correct the existing corner2 renderer convention. Video rendering failure does not invalidate numerical results.

Report separately accounts for calibration, zero-action checks, data/replays, debug, formal updates, dev, final test and video rendering without adding parent-stage wall times to their included children. Unknown GPU attribution is labeled unknown. No extra seeds, data-size sweep, combination task or additional retraining is authorized by this protocol. End with one next step supported by results.

Commands: `pixi run doctor`, `pixi run round2-preflight`, `pixi run round2-calibrate`, `pixi run round2-collect`, `pixi run round2-train`, `pixi run round2-evaluate`, `pixi run round2-report`; `pixi run round2` runs stages in dependency order and validates completed artifacts.
