Round 3：Codex 自主设计先验，提升少样本策略的泛化

把本文作为已有机器人实验仓库的下一轮执行任务。由当前执行任务的 Codex 自主提出先验和模型设计，完成数据准备、候选生成、模型实现、训练、闭环评测、可视化和报告。直接推进已授权工作，不要仅返回计划，也不要完成代码后再询问是否训练。

本版取消独立 Agent API 的前置要求。默认 agent_backend=codex_session：当前 Codex 就是设计 Agent，不需要另外设置 API key、购买服务或调用第二个模型。没有 API 配置不构成阻塞，不得因此只完成准备工作。本文覆盖上一版关于必须真实 API 调用的要求。

本文是交给实验机器上 Codex 的执行规格，不代表训练已经发生。执行时先读取本地 AGENTS.md、README、PROGRESS.md、ROUND2_REPORT.md、数据语义说明、Pixi 配置和已有入口。复用已有 MetaWorld/DP 仓库；本轮结果使用 round3 命名空间，保留旧数据与结果。

1. 本轮只回答一个主要问题

在很少的训练示范不足以覆盖部署变化时，Codex 能否根据任务知识和可用证据，自主提出并实现比普通训练具有更好泛化能力的策略设计？

本轮是探索实验，不预设先验一定有效，不预设不同任务的最佳先验一定不同，也不预设分层更优。暂不扩展成覆盖 composability、控制精度、鲁棒性等所有性质的综合研究。阶段成功和轨迹信息仅用于解释泛化失败。

主要比较：同一任务、同一 N 条示范、同一部署观测和统一训练预算下，普通 DP 与 Agent 设计的候选的未见场景成功率。

明确两个工作阶段，可以由同一个 Codex 完成：

设计阶段：Codex 阅读任务材料，自主提出知识假设、先验组合、模型结构和训练方案，保存提案；随后可根据开发反馈修订一次。

实现阶段：Codex 按已保存的提案实现模块、执行训练与评测。实现中改变设计要记录理由和版本，不能看完结果再倒写最初的设计依据。

本文中的 Agent 均可指当前 Codex 或实际可用的 Codex 子代理；报告明确实际执行方式。当前 Codex 写出的设计就是正式候选，不需要伪造 API 请求来证明 Agent 参与。

2. 执行规模与次序

主矩阵：6 个任务 × 4 个设计 × N={2,5,10,20} × 1 个训练 seed = 96 次完整训练。

四个设计为普通 DP B0，以及 Agent 首次提出的 P1、P2、P3。每任务的三个设计冻结后，在四个 N 上从头独立训练。P1/P2/P3 是候选编号，不预先规定对应某种先验或架构。

反馈阶段：每任务在 N=5 的开发评测后，Agent 最多提出一个修订 P4；若有实质修订，在 N=5 和 N=20 分别从头训练，最多 12 次额外训练。正式训练总上限 108 次。P4 单独报告，不并入初次设计曲线。

先把 pick-place-wall 的观察→设计→实现→训练→开发评测跑通；若该任务环境实现确有阻塞，使用已有 drawer 管线验证流程，并继续修复新任务。不要等六个任务的所有模块都写完才开始首批训练。

执行顺序：

审查仓库与资源；先完成一个新任务的有效数据，由 Codex 写出并保存三个设计。

优先完成 pick-place-wall、assembly 两个任务的 N=5、20 主矩阵，共 16 次训练，给出第一份开发结果快报。

自动继续其余主矩阵，复用已完成的 run，不重复训练。

在各任务 N=5 主候选开发结果齐备后，由 Codex 分析一次反馈，按冻结的修订完成 P4。

所有设计与选择冻结后运行锁定测试，生成最终报告。

单 seed 用于快速找信号。不要把 rollout 数量当作训练 seed 数量；本轮不足以证明跨训练随机性稳定。不要额外自动扩成多 seed 或更多任务，先完成上述规模。

4. 数据：自己采集，所有方法共享

使用现有脚本专家和官方专家，在模拟器中采集每任务 20 条成功训练示范。已有 Round 2 的 20 条示范只有在完全符合本轮划分、观测、目标与版本时才复用；否则重新采集并说明原因。不能为了复用数据破坏本轮划分。

训练集嵌套：D2 ⊂ D5 ⊂ D10 ⊂ D20。同任务的所有候选使用完全相同的 episode ID、原始状态和实际执行动作标签。按预先规定的布局分层顺序选取，不能根据模型表现挑选有利示范。除满足成功和物理合法条件，不用最短轨迹等额外准则筛选“最优的两条”。

每条示范保存 reset 参数、可重放 snapshot、obs/actions、终止原因、成功状态、长度、专家版本、随机 seed 与内容 hash。失败的采集尝试不进入成功示范集，但统计其数量和原因。

调用专家前保存观测的独立副本，并以 obs.copy() 传入专家，防止脚本原地修改数组导致状态标签被污染。动作标签使用实际经过原生动作范围处理并送入 env.step 的值；采集后对每任务的示范做重放一致性检查。

N 是完整示范条数，不是图像帧数。报告各 N 的总 transition 数量和场景覆盖。长轨迹切成很多 chunk 仍只算同一条示范。所有归一化统计仅由当前 D_N 计算，不能用 D20 统计服务 D2。

初次设计的默认示范材料限于 D2。以后模型在 D5/D10/D20 上训练时，不根据这些额外示范重新设计 P1/P2/P3；主矩阵衡量固定设计的数据曲线。候选中的参数拟合、阶段识别和自动标注程序可以在当前 D_N 上运行，这属于该候选的训练过程。若当前 Codex 的既有上下文已经包含额外示范或报告，按照第 8 节披露：N 仍是该策略的训练示范数，但不能声称整个设计过程只接触过 N 条示范。

开发/测试 rollout 不作为新示范加入训练；反馈视频带来的额外信息另记为交互证据。暂不做主动数据采集、专家纠错数据聚合或 RL fine-tuning。

5. 泛化划分：先固定，再训练

每任务建立物理合法的布局空间以及三个评测分布：

IID：与训练布局分布一致、reset seed 不同。

组合留出 C：训练中没有出现过的布局因素配对。它测布局组合的泛化，不等同于任务 A/B/C 顺序组合。

位置/方向外推 E：超出训练因素取值区间、仍在已校准可行范围内的布局。

优先用两个真实独立 reset 因素 a、b 定义 C。例如物体位置因素与目标位置因素；drawer/door 可用柜体位置与 yaw。每个因素预先定义 low/high 两个区间：训练使用 low-low 与 high-high，C 使用 low-high 与 high-low。D2 每种训练配对取一条，随后按均衡顺序增加。实际连续位置仍需随机采样，不能只在四个固定点训练和测试。

low/high 区间之间留间隔；区间内部宽度、精确物理范围、与 E 的关系全部写入 task_manifest。开发 C 与测试 C 使用相同分布的独立状态；它们与训练在“配对单元”上分离。把每档数据实际覆盖画出来，不能把因素的宽区间标签被看过说成所有连续取值已被看过。

如果某任务确实没有两个有效独立因素，不擅自改动力学制造组合任务。改用两个不重叠的位置外推方向作为 C 槽位与 E 槽位，分别准确命名为 E1/E2，并在汇总里说明该任务没有组合留出指标。不要为了图表整齐伪造组合泛化。

具体米数和 yaw 范围由固定版本源码、真实 reset 和独立校准确定，不能在本文之外凭空沿用其他环境的数值。Drawer/Door 优先沿用 Round 2 已校准可行范围，保留其修复后的几何、joint-validity 和成功定义；本轮重新划分数据和冻结新状态。

校准只能看几何合法性、零动作行为、专家执行和任务目标语义，不根据普通 DP 或 Agent 模型的输赢选择范围。默认每任务每分布先用 20 个独立 calibration 状态验证。专家失败不是不可达的严格证明；若集中失败，排查专家和环境，不能逐个删除专家失败的正式测试状态。

当 reset 范围或几何确需修正时，在训练前记录并重建受影响数据。正式比较开始后不修改成功标准、不按被测策略的表现换题、不删困难测试状态。修复真正的环境错误时版本化并对所有受影响方法一致重跑。

评测量：每个 run 的开发集为 IID 10、C 20、E 20 个固定状态；锁定测试为 IID 20、C 40、E 40。所有方法使用相同 snapshots 和配对的 rollout 随机种子。测试状态不交给实验 Agent，测试结果在所有候选与修订冻结后才生成。

统一 episode 上限为 500 个 env.step；若固定版本有不可绕过的更短时限，先记录并对同任务所有方法一致应用。新任务沿用经审查的原生任务成功定义，确认 reset 时未成功、终止与 success 的语义正确；drawer/door 沿用 Round 2 的物理进度与 joint-validity 标准。把完整成功定义、保持条件和异常状态处理写入 manifest，不能把 timeout 当成功。

冻结 native terminated/truncated 的处理方式；技能切换不能重置 episode 时限。执行 action chunk 时逐个 env.step 检查成功、失败和终止，不能因 chunk 较长继续执行终止后的动作或获得额外预算。

6. 先定义同等可用的部署信息

这一轮学习的动作策略仍是 state-input policy。VLM Agent 看图不意味着最终策略完成了视觉泛化；报告明确这一点。

在生成 Agent 候选之前，冻结每任务共同的 observation schema：原生状态、goal，以及必要且明确定义的对象/目标/固定障碍几何字段。若新任务必须补足原生状态缺失的目标或工具信息，把相同原始字段同时提供给 B0 和全部候选。

静态尺寸、关节轴、关节类型等外部任务知识可以作为 Agent 的先验来源，但逐项记录来源。涉及 episode 中变化的位姿和轴向，必须能由共同部署信息确定；不得只给 Agent 策略增加未声明的实时模拟器 oracle。

Agent 可以派生相对坐标、关系特征、阶段概率、目标残差等，这正是被研究的设计变化。要求记录：由哪些原始字段计算、哪些信息只用于训练、哪些参数属于外部知识。

训练中用已有示范的未来状态构造监督是允许的；运行时不能读取未来状态、专家动作、测试任务 success/completion oracle 或隐藏模拟器阶段来选择技能。若实际使用了新的传感通道，该比较要重新提供给所有方法，或作为独立的“额外信息”实验报告，不能混作结构先验收益。

7. 默认由当前 Codex 直接设计

不要把 API 配置检查设为开始实验的门槛。当前 Codex 阅读 evidence bundle，直接写出第 8 节要求的 proposal.json 与简短设计理由，经过校验后冻结，再实现和训练。反馈阶段同样由当前 Codex 读取开发结果并写出 revision.json 或 no_revision。

若当前工具确实支持不继承既有上下文的子代理，可用它阅读每任务的 evidence bundle，改善设计信息的隔离。若没有此能力，直接由当前会话完成并记录上下文范围，不因此暂停。不要假设嵌套命令能自动继承登录状态，也不要为完成本轮另搭一套服务。

控制的是设计和训练的搜索范围：每任务一次初始设计，包含三个候选；最多一次训练前的实质可行性修订；一次 N=5 开发反馈修订；最多一次 P4 的实质可行性修订。日常编译、shape、设备等 bug 修复不按对话轮数收费式计数，但要记录；不得把基于成绩的新搜索伪装成 bug 修复。仍遵守最多 108 次正式训练。

在训练前保存实际设计内容、简短理由、证据文件 hash、时间、设计版本、backend、可见的模型/会话信息及上下文来源。平台不提供 token、费用、model 精确版本或 session ID 时写 unavailable，不编造 API response ID 或成本。只需可审查的设计依据，不要求隐藏思维过程。

如果现有仓库已经有可用且已获授权的 API 后端，可以自主选择复用并记录，但不要求新增配置；没有或不可用时继续使用 codex_session。API 调用如发生，按真实情况记录，并遵守已有费用限制。不同后端的结果分别标注。

恢复执行时读取已冻结提案，继续未完成工作，不重新生成三个不同候选。提案缺失时由正在执行任务的 Codex 亲自生成，不能用固定占位配置或 mock 结果充数。

8. Agent 能看什么，能决定什么

每任务准备独立 evidence bundle；能使用独立设计上下文时优先使用，否则由当前 Codex 分任务阅读并记录额外已知信息。默认材料：

任务目标、共同 observation/action schema、单位、控制频率和动作范围。

部署变化的语义说明及允许范围；不提供具体开发/测试状态和结果。

D2 的两段完整轨迹的数值摘要、分时段采样状态及动作；不只展示成功最后一帧。

每条示范均匀取 8 张帧，共 16 张，标明 episode/time；同一套相机设置。允许附从 D2 计算的速度、物体相对运动等摘要。

已声明的静态几何与机构知识、可用实现接口、训练和参数预算。

默认不将 D5/D10/D20 的其他轨迹、旧实验胜负报告、专家源代码或奖励函数中的脚本化动作规则加入设计材料。单一会话如果此前已经因调试/采集读过这些内容，写入 context_exposure.md，并将结果称作“Codex 辅助设计的探索实验”，不能声称严格隔离或只凭两条示范发现先验。无需为了补做理想隔离重建整个项目。

具体测试状态和结果始终不能用于设计或调参。无论上下文是否隔离，都不能复制脚本专家作为策略、使用专家接管，或把额外示范偷偷加入低 N 的训练集。设计阶段接触多少信息，与策略实际训练使用多少示范，分别报告。

Agent 自由决定：

使用哪些知识假设以及它们在哪些状态/阶段适用。

输入/输出坐标表示、对象与关系编码、参数共享、合适的几何增强。

阶段/接触模式的监督与推断、动态参考系、辅助目标与 loss 权重。

flat DP、共享骨干的模块结构、带学习选择/终止的层级策略，或它们的组合。

是否把某项约束做成硬结构、软偏好或训练增强；也可以判断不适用。

这些是能力范围，不是给每个任务安排答案的菜单。要求三个候选提出有意义的不同机制，至少认真考虑一个组合方案；若认为组合会冲突或没有依据，可以拒绝组合并解释。不要强制 P3 是所有先验之和，也不要强制所有任务都产生 hierarchy。

为快速迭代，默认保持 diffusion action learning 作为平坦或低层行为模型；高层、编码器、共享方式和 loss 可变。不要把第一次实验扩成全算法 NAS，也不要让候选仅靠增大模型或增加示范取胜。

Agent 提案必须结构化包含：

candidate_id, knowledge_hypotheses, evidence_refs,
predicted_generalization_gain, applicability, failure_conditions,
architecture, modules, observation_transform, action_transform,
losses_and_weights, augmentation, training_schedule,
hierarchy_selection_and_termination, chunk_transition_handling,
required_train_labels, required_runtime_inputs,
parameter_budget, implementation_steps, confidence

每个知识假设写明来源是外部常识/几何规格、D2 观察，还是未经证实的推断。loss 必须指定作用对象、单位/尺度、权重和适用条件，不能只写“加入几何 loss”。分层必须说明高层输出、低层条件、切换判据和训练方式。

不向 Agent 暗示某任务必须对应某先验；可以给一个与本轮任务无关的 schema 示例，但不要给现成的 drawer/assembly 配方。

9. 把提案编译为可训练模型

提供小而清晰的插件接口：观测编码、动作编码/解码、附加监督/增强、结构构建、运行时路由。先实现真实提案所需的模块，共享可复用实现；不要预先写完一个庞大先验库才开始训练。

每个候选关联原始 proposal hash、实现配置、代码版本与实现差异说明。Codex 可修复 shape、单位、设备、可微性等实现问题。若修复改变知识假设、硬/软约束或结构语义，由 Codex 保存对应的正式修订并说明依据，计入第 7 节的设计修订预算，不能静默改写已冻结提案。

编译前检查数学和信息可用性。针对具体提案做必要验证：坐标变换往返、动作重建、合法增强的状态/目标/动作一致性、模式切换后动作连续性、没有 runtime oracle。不能仅以张量 shape 正确认定先验成立。

尤其注意：

相对坐标只用于局部交互时，若丢弃全局障碍或可达性信息，可能损害任务。是否保留由 Agent 提案决定并评测，不能手工掩盖失败。

仅旋转对象并不能自动保证固定机器人、重力、障碍下的完整环境旋转等变性。不能把无效示范变换当作合法增强。

动作旋转先在物理 xyz 增量中处理；方向量不含平移。沿用 Round 2 的旋转动作范围修复，不在局部坐标里错误裁剪原生世界动作立方体。

动态参考系必须说明整个 action chunk 使用哪个时刻的变换；不能解码时偷偷读取未来真实物体姿态。

模式切换、技能选择必须闭环使用共同观测。允许 Agent 选择固定/动态 chunk 执行长度，记录推理次数和延迟；这类收益不能全部归因于表示。

首轮不换原生控制器。不把解析专家控制律、专家接管或测试期间搜索最优动作包装成 learned policy。

若候选不成立，保留 invalid/unimplemented 状态与原因；不根据成绩把失败候选从结果中消失，也不无限生成候选直到得到正结果。

10. 训练公平与默认设置

B0 沿用 Round 2 的有效 state-input U-Net DP 实现，使用本轮共同的全部原始观测。先核对旧模型与代码的行为，不弱化 baseline。

默认采用已有设置：obs history 2、prediction horizon 16、execution horizon 4；U-Net widths [64,128,256]，time embedding 128，kernel 5，groups 8；batch 128；AdamW lr 1e-4、weight decay 1e-6、betas (0.9,0.999)，grad clip 1；20,000 updates；epsilon prediction、100 diffusion training steps、DDIM 16、eta 0、EMA 0.995。以仓库实际已验证实现为基础，差异记入 manifest。

沿用 Round 2 的 DDIM clip_sample=False、thresholding=False，动作解码回世界坐标后才应用原生动作范围，避免局部坐标中的错误裁剪。复用经验证的轨迹末尾 mask 和历史初始化逻辑。

所有正式 run 从头初始化；不同 N 不从 N20 或较大数据模型继承权重。默认 seed=0，尽可能配对可比模块的初始化和数据顺序，但不要声称不同结构能够逐随机数完全匹配。

主比较统一使用 20k 时的 EMA，不在测试集选 checkpoint。记录训练曲线并保存 5k/10k/20k 恢复点；不为追逐正结果单独延长某个候选训练。学习率等常规超参本轮固定；Agent 可以指定附加 loss 的调度与分层训练分配，并明确记账。

训练预算按整个系统计算。每次更新采样的底层 demonstration chunks 总预算为 128；模块可以共同处理同一 batch，但不能让每个技能分别获得一份完整的 20k×128 独立训练预算。多阶段训练把全部 optimizer updates 相加计入 20k。高层及辅助模块联合更新时记录其计算量和标签来源。

默认总可训练参数不超过 B0 的 3 倍，允许通过共享骨干或缩小技能网络满足限制。报告实际参数、训练墙钟、GPU 时间、推理延迟与执行重规划次数；相同 updates 不等于相同 FLOPs，不声称严格等算力。

相同数据的几何变换、重标注、轨迹切片是设计的一部分，记录类型与数量；它们不能调用专家生成新轨迹。分层的阶段标签可从当前 D_N 和明确规则生成，部署时选择器不能获得同样的隐藏真值。

运行全部通过已有 Pixi 环境，沿用现有 GPU 选择。正式训练用独立子进程顺序运行，保留 Round 1/2 已解决的跨 Trainer CUDA graph 状态隔离。支持完整 checkpoint 恢复，重启前确认原进程是否仍在运行。

11. Agent 开发反馈与修订

对每任务 N=5 的 B0/P1/P2/P3，仅收集固定开发集结果。向反馈 Agent 提供原提案、训练曲线、分布成功率、失败诊断，以及按预先规定规则选出的最多 8 张失败/成功对照帧。不要从测试集取视频。

要求它先指出证据支持什么、不能支持什么，再输出一个具体 P4 或 no_revision。P4 可以改适用条件、表示、loss、组合或 hierarchy；必须说明相对于原候选的唯一主要修订意图，并列出所有实际变化。

如果 P4 可实现，在 N=5 和 N=20 从头训练并做同样开发/测试。不给它增加示范或训练步数。为各 N 的最终系统选择设计时，依据开发集 (C_success + E_success)/2 最大者，平分则 IID 更高，再平分则较小模型，最后按固定 candidate_id 顺序。选择结果在测试前写入冻结清单。

这里检验一次反馈是否有帮助，不做无限自动搜索。P4 获得了 N5 训练模型与开发交互的信息，因此不能再拿它训练 N2 并称作严格的两示范系统。P4 的设计修订次数、rollout 数、反馈帧数和额外训练全部单列。

保留两条选择结果：只在 P1/P2/P3 中按开发集选择的 initial-selected；加入 B0 与 P4 后按同一规则选择的 final-system。明确 B0 回退是否发生；不能只展示测试集上事后最好的 Agent 模型。

每个 N 只使用该 N 的开发结果、在该 N 实际训练完成的候选中选择；P4 只参与 N5/N20，不能进入 N2/N10 的选择。initial-selected 是开发集上的程序化选优，不是 Codex 在初次设计时预测出的赢家，图表必须准确命名。

12. 指标、负结果和可视化

主要指标是各任务、各 N 的 C/E 成功率与其等权均值。任务之间先分别计算再等权汇总，不能让某个任务因 episode 多而获得更大权重。

同时报告 IID 成功率、IID−OOD 差距、相对 B0 的百分点变化、每档示范数与 transition 数、开发交互和训练开销。OOD 提升但 IID 也同步提升时，说明先验可能同时改善了拟合和泛化，不能把全部增益解释为纯 OOD 能力。

绘制并保存：

每任务一张数据曲线：横轴 2/5/10/20，纵轴成功率，分面显示 IID/C/E；B0、P1/P2/P3、initial-selected 清楚区分。

相对 B0 的 OOD 成功率差值热图，保留全部有效候选和负值；无效候选标 NA 与原因。

初始候选经开发集选优的模型与 P4 修订前后的 N5/N20 对比；明确额外搜索成本。

训练与测试布局覆盖图，标明各档真实示范点和 C/E 区域。

相同测试 snapshot 的 B0 与候选并排 rollout 视频，叠加时间、目标、路由/阶段等诊断。每任务至少一个按固定顺序选出的对照，不只挑最精彩的成功例；另展示失败案例。图像和视频都来自真实模拟器。

测试成功率给二项区间；模型差值可按配对 snapshot bootstrap，标明这些区间只反映当前模型的评测状态采样，不包含训练 seed 和数据子集随机性。不能用 loss 降低代替闭环泛化成功。

若所有方法为零或都接近满分，保留结果。先检查专家可行性、状态/动作语义、训练是否执行、IID 是否可学；只有找到具体 bug 才统一修复重跑。无需通过改测试分布强行制造正结果。合理的地板/天花板会成为下一轮设计依据。

本轮可以得出“这些 Agent 提案是否改善了这些任务上的低数据泛化”与“一次开发反馈有无价值”。本轮不能据此证明 Agent 优于人类设计/随机搜索、跨任务通用，或所有任务都需要不同先验。这些对照放在确认有效信号后进行。

提供实际可执行的 Pixi 入口，至少支持 prepare、validate-proposals、train、dev-eval、test、report、resume 和一个 all 入口；入口名字可适配仓库，但 README 要给出准确命令。配置中显式记录 tasks、N、seed、candidate 数、agent_backend、实际可知的设计模型信息、修订预算、训练预算和数据划分版本。

codex_session 模式下，提案和修订由当前 Codex 写入文件，脚本负责校验、训练与评测，不要求脚本独立调用 LLM。all/resume 基于已存在的设计文件推进；需要提案时产生结构化 pending-design 状态，由当前正在工作的 Codex 读取材料、完成设计后立即继续，无需用户接手。不把这样的命令描述为脱离 Codex 会话后仍可独立进行新设计；若会话中断，保存下一步并由恢复后的 Codex 接续。

run manifest 为每个计划配置记录 pending/pending-design/running/completed/invalid/blocked；提案保存后与每次训练/评测完成后原子保存状态。中断恢复不重复采集、设计、训练或测试。先测量前两个完整训练与评测的耗时，再给出剩余预算估算；不要直接保证 Round 2 耗时可线性迁移到新任务和分层模型。

报告开头直接回答：实际由当前 Codex、子代理还是 API 完成设计，接触过多少示范、历史信息与开发反馈；实际完成多少 run；哪些候选在哪些 N/分布帮助或伤害泛化；Codex 为什么选择了这些设计；反馈后有没有改进；有什么实现失败和结论限制。附所有方法的完整成绩，不能只列 winner。

只把真实缺少的仓库、算力、依赖或无法修复的运行错误记为 blocked，列出已尝试的修复和恢复命令。没有 API key 不构成阻塞。不要把设计或准备完成写成训练完成。
