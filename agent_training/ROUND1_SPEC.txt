5. 数据格式与复现

采用简单 HDF5 或等价的明确数组格式；不要先建设复杂数据平台。每个 episode 至少保存：

obs：形状 [T+1, D] 的原始状态；

actions：形状 [T, 4]，与产生下一状态的实际 env.step 动作一致；

rewards、success、terminated、truncated：长度 T；

episode_id、task_name、seed、采样任务参数、真实初始基座位置；

能恢复 episode 的任务设置和初始模拟器状态；

固定版本、数据 schema 版本和文件 hash。

对初始状态复现，不能只假定保存 qpos/qvel 就足够。任务目标、模型位置、mocap/控制状态、时间限制、环境历史缓存也可能相关。优先让“固定任务参数 + reset seed + 必要 snapshot”的组合确定地恢复状态，并通过测试证明。

dataset_manifest.json 应列出所有 split、20 条训练轨迹 ID、初始条件 ID、位置范围、hash 和排除项。正式训练开始前冻结 manifest。原始数据保持不变，表示变换在 loader 中完成。

首轮只允许 train20 进入正式优化器和 normalization。train_pool 中剩余 80 条不能悄悄参与训练、预训练、标注学习或统计估计。

6. 两种表示的精确定义

raw：使用选定并记录的原生可观察状态向量。

relative：对位置块做如下可逆替换：

[
(p_{hand},p_{handle},p_{goal})
\mapsto
(p_{hand}-p_{handle},\ p_{handle},\ p_{goal}-p_{handle}).
]

具体要求：

保留 handle 的世界坐标；机器人本体、夹爪、四元数和其他原始信息不丢失。

若原生向量包含历史状态块，每个历史块用自己对应时刻的 handle 进行变换。单个当前 goal 相对当前 handle 表示。

Native reset 的历史 padding/占位必须按照已核实 schema 处理，不能无条件将零填充当真实过去位置。需要改变 padding 策略时，两方法一致，并记录其属于环境输入适配。

DP 另外使用 2 步 observation history；两方法均保留同样的 native packed history，避免只在一边重复/删除历史。

实现正向和逆向变换，验证 raw→relative→raw 在 float32 下近似恢复，容差 1e-6 或经数据尺度说明后的等效容差。

两方法输入维度相同，网络架构和参数量完全相同。只有 representation 和由其训练数据计算的 observation normalizer 不同。

变换先于 normalization。每个表示的 per-dimension mean/std 仅从同一份 train20 的输入状态计算；std 下限设 1e-3 并记录常量字段。不用 dev/test 或整个 100 条池的统计，不将 OOD normalized observations 强行裁剪到训练范围。

动作保持环境原生 [-1,1] 约定，不从示范 min/max 再做一遍 action normalization。平移原点不改变增量动作，不旋转或平移 action labels。

不引入 success、剩余步数、专家阶段标签、未来真实状态等额外 policy input。success 仅用于采集、评价与结束。

7. 模型和训练配置

使用 conditional 1D U-Net 的 action diffusion。优先复用仓库已有可靠实现；若没有，用官方 DP 必要模块或遵守许可的精简实现。

正式配置起点固定为：

n_obs_steps: 2
prediction_horizon: 16
n_action_steps: 4
action_dim: 4
unet_down_dims: [64, 128, 256]
diffusion_step_embed_dim: 128
kernel_size: 5
n_groups: 8
batch_size: 128
optimizer: AdamW
learning_rate: 0.0001
weight_decay: 0.000001
betas: [0.9, 0.999]
max_grad_norm: 1.0
train_updates: 20000
lr_schedule: constant
diffusion_train_timesteps: 100
beta_schedule: squaredcos_cap_v2
prediction_type: epsilon
inference_scheduler: DDIM
inference_steps: 16
ddim_eta: 0.0
clip_predicted_clean_actions: true
ema_decay: 0.995
train_seed: 0
checkpoint_updates: [5000, 10000, 20000]

确保 scheduler 的训练与推理噪声参数完全一致，不依赖未记录的库默认值。Loss 为 valid action entries 上的 epsilon MSE，不增加其他 regularizer 或 auxiliary head。使用同样的 EMA 更新规则，开发与测试均评价 EMA 权重。

若现有可靠模块的接口不能直接接受以上命名，可以映射到等价参数并记录；不要为省事替换成 MLP regression 再称其为 DP。必要的兼容性调整在四次正式训练前统一冻结。

时间对齐必须明确

在时刻 t，条件为 (o[t-1], o[t])。

预测目标为 (a[t], ..., a[t+15])。

闭环执行预测结果的 [0:4]，随后重新观测和生成。

episode 起点重复最早可用 observation；episode 尾部 padding 不能跨到下一 episode，缺失 action targets 使用 valid mask，不计入 loss。

不直接沿用假设 action sequence 从 t-1 开始的第三方切片代码。用人工构造的时间索引样本检验实际对齐。

一个 chunk 执行中若 success 或 terminated/truncated 发生，立即结束该 episode；不能把剩余动作施加到自动 reset 后的新 episode。

公平配对

同一任务的 raw/relative 使用相同 train20、网络初始权重、窗口采样流、diffusion timestep 和训练噪声 RNG 流、batch size、更新次数、optimizer 和 EMA 配置。使用独立 RNG 管理 loader、训练 diffusion、开发采样和测试采样，避免视频或额外日志改变随机序列。

正式训练默认单进程按可用 GPU 顺序运行；无需引入多 GPU 框架。若显存不足，优先通过一致的 microbatch/gradient accumulation 保持有效 batch=128。所有资源相关调整必须在配对模型上相同；不能只给一个模型更长训练。

两任务专家都能完成若干原生 episode；采集前后 observation 不被专家修改。

Normalizer 只读取 train20，保存其来源 ID/hash；人工极端 OOD 值不会被输入裁剪吞掉。

网络输出形状、scheduler 去噪、梯度、EMA、checkpoint 保存/恢复正确；恢复不丢 optimizer/RNG/采样位置。

9. 正式执行、checkpoint 选择和测试

按 run manifest 完成全部四次正式训练。每个 run 保存完整配置、数据 hash、normalizer、参数量、训练日志、EMA checkpoint、恢复状态、耗时和硬件信息。

在 5k、10k、20k 各 checkpoint 上，用同一组 20 个 dev 初始条件和固定独立采样种子评价。选择规则固定：

dev success rate 最高；

并列时选成功 episode 的平均完成步数更少者；

仍并列选更早 checkpoint；若没有成功 episode，完成步数记为空，直接用更早 checkpoint。

四个选定 checkpoint 固定后，才运行最终 test_iid 与 test_ood。每个模型 20+20=40 个 episode，共 160 个正式测试 episode。每个初始条件使用固定的 diffusion 初始噪声 RNG；同任务的两个表示使用相同 episode seeds。

成功定义：原生 info['success'] 在时间上限内触发即算成功，并记录首次成功步数。保留 terminated/truncated 与失败原因；不改变环境奖励/成功阈值来改善结果。

不要因测试分数低就返回修改结构、数据量、checkpoint 选择规则或 OOD 范围后覆盖旧结果。真正代码错误可以修复，但必须保留旧记录、说明 invalidation 理由，并重跑受影响的完整配对比较。
