# cut_v4 子任务合理性与 agent 接口审阅

核对日期：2026-09-21。本报告是开发者对冻结 API 设计的审阅，不修改
cut、prior 或调用契约，也未启动新的 API、训练或机器人执行。

**判断：三个子任务有明确用途，四个 policy 的差异也有实质内容。
现有文档足以说明技能库的构成；供 agent 无歧义实现、选择、调用和交接
的契约仍需补齐。最主要的问题是工具技能的训练支持、目标/位姿生成
接口、停止与交接语义，以及旧执行器对新分组的兼容性。**

## 2. 子任务与各 policy

| Policy | 合理之处 | Agent 已有的控制/反馈 | 仍需完善 |
| --- | --- | --- | --- |
| `access_clearance_v1` | 单独提供工具接近/换位，适合在物体技能之间调用；运动学与障碍约束直接服务于这个职责 | 工具目标位姿、approach/depart/transfer、保护对象；位姿误差、间隙、阶段和状态 | 工具目标如何生成；模式覆盖；到位但未停稳时的控制责任 |
| `push_boundary_v1` | 局部边界、孔洞与接触响应可以共享于不同形状；固定物理实例和目标分配清楚 | 实例、目标轮廓/位姿、方向假设、保护对象、退出位姿；误差、响应、分歧和停滞 | 几何可用性的可计算判据；是否支持高层约束接触侧/运动范围；输入转换和响应模型资产 |
| `push_visual_v1` | 同一搬运任务的另一种表示，利用双视角时序与短动作序列 | 与几何版相同的目标接口；视角可用性、跟踪/动作不确定性；切换时重置动作序列 | 与几何版的具体选择条件；共同感知依赖；原始观测到目标 raster 的完整工具接口 |
| `align_local_v1` | 对已暂存/近目标物体进行短动作纠正，六次回访加两次晚期复用提供了相应例子 | 实例、目标、保护对象、容差、最大纠正次数；误差、响应、邻物变化和重试反馈 | “近目标”与局部适用范围；计次/停止定义；与搬运的可操作切换条件 |

### 工具移动：用途合理，覆盖是四者中最需要补证据的部分

四段只有两种显式训练 condition：两段 `approach`，两段 `transfer`。
监督支持的 1,072 条有限关节命令不是 1,072 次独立工具移动。

| 片段 | 有限命令行 | 原始监督首尾时间差 | EE 净 z 变化 | 最后约 0.5 秒平均 EE 速度 |
| --- | ---: | ---: | ---: | ---: |
| A 初始接近 [0,600) | 340 | 19.946 s | -28.00 cm | 3.07 cm/s |
| B 初始接近 [0,420) | 352 | 13.946 s | -31.19 cm | 2.32 cm/s |
| A 换位 [6150,6340) | 190 | 6.299 s | -0.34 cm | 3.30 cm/s |
| B 换位 [2750,2940) | 190 | 6.300 s | +2.15 cm | 4.69 cm/s |

B 换位确有上升，不能说数据完全没有抬起行为。但 `depart` 单独调用和
从接触状态脱离、较大范围换边的支持没有被分别建立。两段主要初始
接近又都来自类似的高起始位姿。API 拟议内部离开/平移/下降/稳定阶段
及运动学提议能否补足这些变化，需要明确学习部分和解析部分的责任。

建议由 API 对现有示范中的相关行为进一步建立模式覆盖映射，判断哪些
兼容片段可以复用到工具组，并给出每种调用模式的进入/退出支持。
此建议没有手工选择新切点或修改原分组。

### 两个搬运 prior：属于有意义的可替代方案

几何版提出局部接触候选、预测物体响应并短视野重规划；视觉版直接
使用双视角和目标 mask，产生短动作序列。它们共享任务参数而分别训练，
适合 agent 在同一个搬运目标下选择。

视觉版仍依赖实例跟踪、当前 mask 和目标轮廓转换。它可以应对精确
轮廓/位姿较不稳定而身份仍可靠的情况，不能据此认为两种方法在感知
失败上完全独立。当前选择说明也还是“几何可靠”“视觉可用”等文字，
需要将这些描述对应到公共观测量或能力检查结果。

两版都把接触点、重接触和退出动作留给 policy 内部。Agent 可以指定
最终局部目标，但目前没有明确接口保证“沿当前这一侧推”“只执行
某种接触模式”或“保持给定运动平面”。若要求高层控制这些细节，应让
API 明确对应控制权限；若保留当前职责，高层调用到的是完整搬运技能。

因此，这一版接近“工具接近/换位 → 整体搬运 → 局部纠正”的分工，
尚不是一个单独暴露给 agent 的纯平面推技能。搬运组保留自由移动、
抬起和重接触监督；若采用 2D 接触运动 prior，需要明确其适用阶段、
坐标/高度条件及与其他阶段的交接。不能对整组动作不加区分地施加
同一个平面约束。当前模式化设计为此提供了空间，但没有给出该约束。

### 局部微调：适合保留，但其适用域需要定义

图像抽查可见 D-like 的后续摆正、flanged piece 的转动/位置调整、L-like
晚期摆正、R-like 后期修正。这支持一个局部纠正职责。API 已考虑自由
换位和接触动作使用不同输出分支，因此“片段包含抬起或较快动作”本身
不是否定这个分组的理由。

需要补齐的是 `near-goal`、`local envelope`、`trust region` 的确定方式。
这些片段尚无已计算的物体初始目标误差分布，不能由片段发生得晚就
推出适用范围。Agent 应能从当前误差、可见性和可达性等信息判断是否
适合调用微调，以及何时转回搬运；阈值或能力模型应由 API 按证据定义。

## 3. 当前接口最关键的缺口

### A. 从场景到合法调用参数的链条还未形成具体工具接口

现有 API 已规划感知、跟踪、布局、目标转换和碰撞检查组件，不能说它
完全忽略了这些。缺口是它们尚未提供 agent 可调用的具体输入输出契约。

例如 `access_clearance_v1` 要求一个完整的 `T_base_ee` 工具目标；agent
仅知道“去这个物体另一侧”时，仍需要获得可达的目标位姿。目标位置、
姿态、间隙和路径检查不能靠模型随意填写数字。同样，物体 ID、目标
footprint、方向假设和受保护对象应来自一致的场景与转换接口。

应明确并实现：当前场景/实例查询、局部目标构造、工具接近或退出位姿
生成、适用性检查，以及这些结果的坐标系、有效期和失败返回。这里
描述的是需要的能力，不是声称这些命名的工具已经存在。

### B. 到达目标、停止、完成与可交接需要一致的语义

**四个 access 片段最后一行的原始关节命令全部非零。** 全部 28 个
片段中有 26 个如此，只有两条轨迹的最后片段末行是零命令。这与真实
连续示范相符，本身不意味着边界错误。

但 access 文档一处允许 `reached-waypoint-but-not-settled`，目录使用
`READY`，公共状态列表又没有这两个名称。几何/对齐完成还要求连续五次
有效观测和适当工具间隙。目录已将 stopping 列为 access 的职责，
但还需将减速/保持、何时不再应用下一个预测动作、运动中的到位是否
可直接交接，以及下一技能接受哪些状态统一起来。执行监控可承担其中
明确分配的职责；当前几处说明尚未形成一个一致的状态契约。

“五次有效观测”也需要定义时序：按新相机帧、去重后的有效观测还是
机器人采样计数；重复图像和不同相机到达时间如何处理。计数不能被
不加说明地解释成固定的物理稳定时长。

### C. 可选退出位姿 E 的缺省行为和训练支持

E 用原段最后监督行的工具位姿，为物体已到位后的离开动作提供条件，
这个设计有明确用途。在线则要求 agent 根据下一次接近计划提供 E。

公共说明同时规定 E 可省略，省略时执行经过验证的 clearance retract。
所有 24 个物体组片段的条件/标签均给出 E；尚未定义缺省 E 的训练方式，
也未指定默认 retract 由哪个组件生成/执行、在哪里完成。需要 API 补齐
有 E、无 E、目标已达成但工具未退出三种情况的行为与返回语义。

### D. 可计算的选择条件、结构化参数和切换协议

已有的实例/目标、保护列表、容差、时限、状态/误差、历史记忆等字段
覆盖了主要需求。仍需具体规定字段类型、坐标与单位、必填/可选项、
ID/场景版本失效、同 call 继续和新 call 重置、取消与抢占，以及切换
policy 时可转移的数据。目录允许转移显式跟踪/响应摘要，需要给出
这些摘要的结构和坐标约定。

几何版“不确定性高”、视觉版“有可用视角”、微调“局部范围内”等
描述，应对应观测或能力检查，而不只是 agent 自行解释的形容词。
两个模型的不确定性也不能未经定义就当作可直接比较的同一种分数。

## 4. Buffer 是否服务于训练稳定性

数值检查确认：非终端两侧的 15 行 buffer 实际约为各 0.5 秒。它们
主要是上下文，四段跨组复用另提供 1,370 次监督使用。

这对历史初始化和交接证据有用；它没有自动给每个技能增加结束后
停稳、入口偏离时纠正的动作监督。因此，buffer 设计与 prior 的兼容
关系基本讲清楚了，仍要将“稳定执行”的目标落实到具体监督或执行
监控职责。不能由存在 buffer 就断定交接已经稳定。

## 5. 现有代码接口不能原样承接 cut_v4

[design.py](../policy_training/design.py) 的 `POLICIES` 与配置/包验证
固定为 `contour_push`、`visual_push`；
[旧数值接口](../policy_training/INTERFACE.md) 还要求两个 prior 使用
同一份 prepared dataset，现有 sampler 也采用公共 K 和 loss_weight。
这些属于旧轮次的正确约束，并不是本次修改造成的回归。

新执行接口需要表达三个 sub-dataset 到四个 policy 的映射，支持各组
监督和各 policy 的有效样本集合，以及两个搬运 prior 的共享来源。
不能仅换 policy 名称后仍从三组并集为每个模型采样。

新版还提议预训练分割/视觉编码器和几何资产。旧锁定环境及安全沙箱
对依赖和资产有明确限制；实现阶段需要事先解决其依赖供给和接口，
并保留具体 prior 及预处理由 Runtime API 实现的所有权。

## 6. 建议的下一步

保留三子任务与四 policy 的总体结构。先让 Runtime API 补充工具技能
各模式的训练支持、完整调用 schema、场景到目标/工具位姿的转换接口、
统一停止/交接状态、E 缺省行为和可计算的技能选择条件，再进入独立
实现与训练。接口例子应覆盖首次接近、搬运切微调、需要换位、切换
搬运 prior、目标达成但工具未退出，以及缺失所需输入等实际调用情况。

这些是审阅建议；本轮没有代写科学实现、追加 API 会话、修改已提交
设计或启动训练。原设计完成的事实与此次审阅提出的接口工作分别记录。

## 7. 追加核对：为何没有单独形成平面推组

2026-09-21，针对用户关于 object-centric 与水平 EE pose 的追问：

- 原始两条轨迹分别有 [9015,4,4] 和 [7730,4,4] 的 T_base_ee，
  全部 16,745 个变换有限，包含 XYZ 与完整旋转矩阵。read_steps 向 API
  提供这些字段；read_motion 提供 XYZ 范围、首尾位置与速度摘要。
- 保存的实际调用显示，API 只对两条完整轨迹分别做过一次 24-bin、
  20-bin 运动概览；没有进一步细分区间调用 read_motion。每个 bin
  约覆盖 12–13 秒。另显式查看 69 / 59 个不同索引的原始状态。
  这些是工具请求记录，不是推测它阅读了所有原始行。
- 原文明确识别 planar pushing、low-height travel、lifting 和 recontact，
  并明确选择保留完整 recontact cycles。其几何 prior 已使用物体局部
  边界与目标相对表示。因此问题并非完全没有 object-centric 概念或
  没有 EE 位姿，而是这些信息没有成为更细切分的主要依据。
- 当前 prompt 先按局部目的/结果确定 subtask，再设计 prior；它允许按
  “搬完一件物体”形成组，没有要求以共享的交互模式、有效动作自由度
  和物体相对规律进一步确定技能粒度。这是对 prompt 与提交结果的
  分析，不是关于模型内部原因的确定因果结论。

基座坐标中的位置/姿态均已保存；尚缺的是经核验的桌面参考平面、
工具接触点几何，以及逐帧物体位姿/接触标注。若桌面法向为 n，
工具位置为 p，则沿法向高度与切向位移可以由 n 和 p 导出；基座 z
不可未经核验就直接当桌面间隙。缺少这些衍生量增加识别成本，但
不是原始 EE 水平位置丢失。

后续设计可要求 API 先识别物体/工具相对交互规律、各模式的有效动作
空间和局部效果，再据此组成可复用子任务并细查模式转换边界。
运动证据工具可展示连续 XYZ/姿态、切向/法向速度和同步图像，具体
模式与切点仍由 API 决定。平面运动还需结合物体移动与相对几何区分
接触推和空中横移；不能仅用高度近似不变替代子任务判断。
