## Task interpretation (verbatim API output)

The intended autonomous task is to arrange physical letter instances into a currently requested word under explicit layout constraints, including completely unseen identities and physical shapes. These two demonstrations show a Franka-mounted long slender rigid pushing tool moving seven flat brown letter-shaped pieces on a white surface. Third and wrist views support planar pushing, inner/outer-edge engagement, changes of contact, elevation for re-positioning, temporary displacements and revisits. The apparent inventory can be described visually as W/M-like zigzag, annular O-like, R-like, L-shaped, D-like and two differently oriented crossbar pieces (H/I-like). These names are mnemonic associations to visible instances, not provided letter labels. The final images look consistent with HI beside WORLD viewed sideways, but neither a requested word nor success is annotated. In particular, endpoints are not proof of success.
The motor learning unit is not an episode or a letter category: it is a specific instance-to-achieved-placement invocation. Temporary R/D/I/H moves are distinguished from later revisits. Hindsight endpoints provide explicit spatial training conditions, with causal live-state inputs kept separate. Word understanding, inventory feasibility, upright semantic interpretation, layout and sequencing remain explicit upstream responsibilities supported by declared models. No assumption that a new word is merely a rearrangement of the demonstrated alphabet is acceptable. Autonomous deployment still requires perception weights, verified backend/safety semantics and, for metric/projective layouts, additional commissioned geometry assets; these are obligations, not assets claimed present.

## Goal conditioning (verbatim API output)

COMMON LABEL RULE G: each segment pins exactly one physical referent and one hindsight achieved placement, not a verified original intention. Its specified goal anchor is the last included paired row, and its goal box is in ORIGINAL third-camera pixels (left,top,right,bottom), before undistortion. Extract only the selected letter foreground from that box, preserving holes and excluding tool/robot; map it through the supplied third Brown-Conrady undistortion with K unchanged. The resulting full-image binary foreground, tight RGB crop, centroid and template-relative orientation are the training-only spatial goal. Identify the foreground by class-agnostic segmentation plus overlap/appearance association to the stated reference; these boxes and visual mnemonics resolve the referent, not a future annotation of which letter/objective to choose. No global word label is assigned. Goal contours/poses are inferred, not verified ground truth.
Current observations are independently segmented and tracked CAUSALLY. Never feed a backward-smoothed current pose or the anchor image as a current observation. Offline bidirectional association may establish which instance a target label refers to, but cannot supply causal current features. Instance selection can be hindsight-labeled while the selected current mask must come from the causal detector. Initialize a new segment's causal tracker from its first available frame with automatic component proposals; associate its episode-local track to the stated referent. If occlusion prevents initialization, early rows have invalid selected-mask features until the track can be established from available history. Use full goal foreground/crop, not just centroid, to disambiguate orientation where possible. Template-to-goal similarity/projective registration supplies orientation and an ambiguity set; ties caused by symmetry stay ties. If the anchor cannot be segmented/associated, or goal registration is inconsistent with a planar rigid piece, suppress condition-dependent loss for that segment and report the derivation failure; do not invent a pose or seek an unspecified internal objective. Determining exact masks is an implementation obligation, not an unresolved choice of goal.
At deployment the HLA chooses an actual scene instance and a spatial placement. The observation pipeline supplies its shape/template, confidence and orientation hypotheses. A deterministic renderer generates the corresponding goal foreground in the same chart from chosen position/orientation; a verified tabletop homography is required when perspective makes a similarity transform inadequate. User metric layouts require that additional commissioned plane calibration; without it accept only valid image-layout requests or report calibration_required. The HLA cannot supply an unmeasured metric object pose by fiat. Upright semantic direction is supplied by the declared recognizer or a user target image; if ambiguous, autonomously pause/report ambiguity, with any optional user clarification explicitly counted as lost autonomy. Goal updates that change the desired placement or selected instance require a new call. Re-contact and clearance changes for the same fixed goal are internal progress, not conditioning switches.

## Portfolio rationale (verbatim API output)

One compatible regrouped motor dataset, two substantive callable alternatives. The evidence repeatedly shows instance-conditioned planar relocation with continuous re-contact, not seven unrelated letter skills. Stage versus final placement, shape, displacement, orientation and tool approach are expressed through observations and the fixed image goal, so separate per-letter/stage networks would waste scarce data. A boundary-graph prior deliberately exposes current shape/topology and contact-side geometry, while a dual-RGB temporal prior retains appearance, local tool cues and occlusion history that a contour bottleneck can discard. They train independently and offer the HLA distinguishable operating regimes, not different seeds or synonyms. Both cover the same demonstrated approach/contact/correction responsibility; neither is mandatory upstream of the other. One generic combined model would hide these differences, but adding separate translation/rotation/approach policies would impose unsupported hard phase boundaries and multiply data scarcity. Separate responsibilities would be justified by future evidence of incompatible tools, lifting or contact modalities, not merely by a different glyph name. Two policies are a design choice, not an empirical optimum.

## Model inventory (verbatim API output)

Available assets: two original paired recordings, RGB/depth references, states/actions and per-episode metadata; third K/distortion/T_base_cam, wrist calibrated K/distortion/T_flange_cam, and TCP xyz [0,0,0.2], rpy [0,0,-90] degrees. Calibration reports 4.420426-pixel reprojection RMS and 3.230258-mm consistency, so fine pose tolerances require uncertainty. The supplied T_base_board is NOT verified to be the tabletop/piece-top plane. Depth scale and RGB registration are unverified and unused.
Shared deterministic components to implement later: exact paired-record loader and validity masks; Brown-Conrady undistortion using the calibration block (not mixing the different wrist factory and calibrated intrinsics); wrist camera pose from T_base_flange*T_flange_cam; tool projection from T_base_ee using the recorded TCP, checked against images before use; timestamp/frame-number freshness features without clock realignment; instance/goal coordinate chart conversion; contour sampling, curvature/normals, signed-distance maps and registration; goal renderer; status/progress and neighbor-motion monitor. Robot/tool image masking requires an automatically detected tool silhouette or a commissioned geometric tool model; TCP location alone does not supply its width. Any model dimensions/robot geometry used for safety must be supplied and validated. No metric inverse projection is needed for the primary image-chart policies. A verified plane homography and tool/table clearance calibration remain commissioning assets for projectively correct/metric layouts and workspace safety.
Shared learned perception, NOT provided: a class-agnostic instance segmentation model with automatic full-scene proposals and calibrated uncertainty, a causal appearance/flow association model, and an open-vocabulary character plus upright-orientation recognizer. Supply licensed/versioned weights and required generic-object/character supervision in a later authorized implementation; these recordings provide neither masks nor a sufficient alphabet-training set. Goal-box hints here are training label anchors, not human clicks required for deployment. Perception must handle unseen shapes using current pixels, not retrieve a known letter mesh/font. Track IDs are arbitrary and episode/scene scoped; IDs never encode spelling. Assignment/registration uses appearance, predicted causal motion and masks; ties, touching objects, lost tracks and visibility gaps are explicit invalid/ambiguous outputs. With no suitable weights these pipelines are not autonomous or runnable; adding per-move human segmentation would violate the intended autonomous operating mode and must not be silently substituted.
HLA support, distinct from motor policies: deterministic word multiset/inventory assignment and geometric layout/clearance feasibility checks; the above recognizer; and a layout renderer. The external HLA selects order and staging locations from current maps, observes changes and chooses the next call. No new learned task planner is claimed or trained from two episodes.
Policy-specific learned components: contour_push has an independently trained variable-size boundary graph encoder, temporal state encoder and 7-command velocity distribution head; optional auxiliary next-observation displacement/contact-affinity heads use only within-segment future targets and are discarded or used predictively online. visual_push has its own independently trained dual-view RGB/goal encoder, causal recurrent/attention state and 7-command velocity distribution head. Frozen generic visual initialization is permitted only if its weights/version and training overlap are disclosed; otherwise train from scratch and expect limited data. They do not share motor weights or ensemble outputs. Both may share the same frozen perception/coordinate conversion assets. Their action supervision is finite action_json.dq, not state dq; missing commands carry zero loss, never fabricated zeros.
Shared action backend, mandatory but unavailable here: recording-controller verification of joint order, units, command hold/update semantics, robot limits, watchdog/stop, singularity and workspace limits. Decode the learned 7-vector directly into that verified joint-velocity interface; do not reconstruct missing commands from v/w or integrate measured dq. v/w/spacemouse and target_pose remain exact source fields for audit; target_pose is not a supplied goal label. No inverse-kinematics, force controller or contact sensor is assumed. tau_ext is a measured residual feature/possible anomaly cue, not calibrated contact force. All perception, converters, monitor, policy networks and decoder must be delivered as executable artifacts later; none is implemented, trained or certified in this stage.

## Generalization design (verbatim API output)

The task requires unseen letter identities AND unseen physical shapes, new words, new arrangements and new layouts. Do not evaluate only permutations of these seven pieces. Segmentation removes the demonstrated spelling/order as a training condition; each call has an instance and explicit spatial objective. Staging outcomes receive their own goals instead of being mislabeled as progress directly toward the final word. The same conditional motor problem is shared across instances, approaches, straight/curved boundaries, holes, rotations and re-contacts. The contour policy receives current boundary geometry rather than a learned class ID or stored alphabet template; the visual alternative receives an instance-marked scene and explicit goal rather than episode position. These choices address shape and layout variation but two episodes cannot establish broad contact/friction competence.
Semantic generalization is separate: an open-vocabulary visual character/upright-orientation recognizer must map automatically segmented instances to the requested character multiset, including multiple distinct instances for repeated characters. Its weights and evaluation set are not provided. It must output competing hypotheses and reject ambiguous M/W or rotated/symmetric readings, not silently resolve them by the demonstrated word. The HLA matches the multiset, reports impossible inventories without moving, and proposes a baseline, direction, center positions, orientations, spacing and margins in the image chart. It can allocate temporary free areas and re-plan after observed displacements. No fixed WORLD order is embedded. A goal renderer uses the actual observed instance shape; accepting an unknown Unicode character is not evidence that either recognizer or motor policy handles its geometry.
Required independent evaluations: (1) held-out identities and fonts/shapes, with words and positions otherwise controlled; (2) new words and repeated-character requests using familiar shapes; (3) new arrangements, obstructed approaches and non-demonstrated layouts; (4) the joint test of unseen identities, unseen physical shapes AND new words/layouts; (5) impossible inventories and visually ambiguous requests. Shape splits must separate physical exemplars and topology/concavity, not just paint or placements. Measure identification/upright error, instance allocation, per-call position/orientation error, neighbor displacement, contact loss, blocked/uncertain calibration, number of interventions and final word readability/stability separately. Also test illumination, camera occlusion, tool visibility, friction and scale changes, with safety envelopes enforced. Evaluate geometric and visual policies independently, then HLA selection by observable uncertainty; no empirical ranking is asserted.
Only leave-one-episode-out development is possible here, and it is a familiar-inventory/scene test, not the required generalization test. New authorized data with independent shapes/materials, alternate fonts, multiple instances and different goals are needed for the required tests and likely for competence. Proposed ablations (evaluation baselines, not extra callable policies) remove goal conditioning, contour adjacency/normals, object-centered features, history or the target-instance marker. Include a demonstration-order replay baseline to expose accidental task memorization. Large image-plane rotations/translations cannot be treated as physically valid arbitrary new demonstrations without consistent camera/geometry/action conversion. No success claims follow from this plan or artifact validation.

## Calling contract (verbatim API output)

Proposed library, not executable software: dataset group instance_relocation supports two independently trained alternatives, contour_push (heuristic boundary_graph) and visual_push (heuristic dual_view_memory). Both are interruptible, closed-loop calls for ONE physical instance and ONE fixed spatial goal, including approach, contact changes, pushing, small corrections and withdrawal. Neither chooses the next letter, a word, or a new staging goal. The High-level Agent (HLA) owns inventory matching, placement/staging goals, ordering, policy selection, cancellation and re-planning. A different instance or spatial goal starts a new invocation; changing observations, contact location or uncertainty does not.
Common caller arguments: scene-versioned instance_id; reference to that instance's current observation-derived foreground template; spatial_goal in the calibrated third-camera undistorted image chart; allowed workspace/obstacle and already-placed-instance references; positional/angular tolerances and maximum call duration. The spatial goal is an explicit image placement: center (u,v) in original 1280x720 pixel coordinates, desired orientation relative to the instance template at invocation, and target foreground silhouette. A pipeline, not the HLA's unaided reasoning, segments/tracks instances and renders the template at the supplied center/orientation. The HLA can instead accept a user-supplied target scene image after instance association. These are IMAGE-space objectives, not claimed metric poses. Large perspective changes require projective rendering from a commissioned tabletop homography; absent that asset the renderer flags its approximation and refuses layouts whose silhouette cannot be realized by a planar rigid piece. No inverse-depth or metric pose oracle is assumed. The image chart, calibration version, reference template, goal and tolerance stay fixed for a call; the current mask/track is updated causally.
For illustration only: after automatic inventory matching, the HLA could request contour_push for scene_12/instance_4, with third-image center (700,420), relative orientation +20 degrees, goal silhouette produced from that instance's template, a proposed 8-pixel/8-degree tolerance, and a 30-second budget. If the edge quality deteriorates but the identity remains trackable in RGB/history, it may cancel and invoke visual_push with the SAME instance and spatial goal, re-expressed against its new invocation template. A word such as CAT alone is not a legal motor-policy call: distinct C, A and T instances, their readable orientation and three non-overlapping spatial goals must first be resolved. Thresholds and selection benefits are hypotheses.
Common observations: original paired third and wrist RGB, q, measured dq, tau_ext, T_base_ee and T_base_flange, timestamps/frame numbers, calibration, validity masks and causal history. Gripper -1/NaN is invalid; it is not evidence of open or closed fingers. No raw depth is required. Policies return a candidate 7-vector of commanded joint velocity plus running/goal_observed/blocked/uncertain/timeout status, track confidence, goal discrepancy, recent discrepancy trend, tool clearance estimate and possible neighbor displacement. Backend interpretation of action_json.dq, joint ordering, rad/s units, update/hold latency, watchdog and limits MUST be verified against the recording controller before any executable command is enabled. Joint_velocity metadata alone is insufficient. Candidate commands are not measured dq and are not integrated as position increments. If required calibration, track, controller verification or fresh observations are absent, return a reasoned unavailable status and request a verified stop, rather than fabricating measurements or zero-filling missing recorded commands.
Proposed execution timing is a verified 20-Hz command interface with latest available 30-Hz observations, explicit image ages and causal buffers. Training preserves every original pairing and timing; duplicated commands at 30 Hz are not independent teleoperation decisions. Do not repair pairings from camera clock differences. The HLA monitors geometric progress and all placed instances; goal_observed is not word success. On stopping, require a new visual stability/readability check and clearance check before the next call. Safety and workspace commissioning, not this dataset, authorize the actual stop and velocity envelopes.

## Capability coverage (verbatim API output)

Coverage map: contour_push and visual_push both learn initial elevated approach from the two W blocks; within-instance perimeter travel/re-contact and long transport from A-W/A-O/A-L and B-W/B-O/B-L; orientation and alignment corrections from A-L, A-D-align, A-I-align, B-R and B-D-align; inner-boundary engagement from A-D-stage and B-D-stage (wrist views at 4800 and 1800); temporary relocation/staging from A-I-stage1, A-R-stage, A-I-stage2, A-H-stage, A-D-stage, B-I-stage, B-D-stage and B-H-stage; and revisiting a previously moved instance from the separate later R/D/I/H blocks. They are alternatives for the same responsibility, not a serial pair. The graph policy is selected when complete contours and tool projection are reliable; the RGB-history policy is an alternative when local contour extraction is fragmented yet instance identity and goal remain valid. These cues can be computed online. Both retain demonstrated withdrawals, elevated re-positioning and the unusual B-R re-contact/posture motion around 4050-4200 instead of discarding corrections.
User word parsing, open-inventory identity recognition, repeated-character allocation, layout construction, infeasibility detection and sequencing belong to declared auxiliary components plus the HLA; they are not learned as verified capabilities from these recordings. There is no demonstrated grasping, object flipping, disentangling stacked pieces, recovery from a fallen piece, deliberate multi-object pushing, large collision recovery, or arbitrary robot homing policy. There is no separate learned general-purpose free-space planner: the observed approach and withdrawal regimes are internal to either relocation policy, and hazardous travel must cause refusal/re-planning. New-shape pushing is a required hypothesis addressed by the geometry-conditioned designs and explicit tests, not an established capability.

## Sharing and diversity audit (verbatim API output)

Mapping: all a_* and b_* segments -> instance_relocation; boundary_graph -> contour_push; dual_view_memory -> visual_push. Each segment has exactly one fixed selected instance and achieved-placement condition, including distinct staging and revisit calls. A segment boundary is not a policy boundary. Both priors use the same observation/action/source contract after explicit conversion to a common image chart and commanded joint velocities. A graph readout still conditions on absolute robot state/tool projection, avoiding a false claim that arbitrary image rotations leave robot joint actions equivariant. No character one-hot, episode index, visible final word or sequence counter is a motor input. Shared perception errors and controller dependencies are common blind spots; the alternatives are not independent safety redundancy. The graph's proposed advantage is sample-efficient transfer of contact geometry when contours are reliable; the visual model's proposed advantage is retaining cues lost by geometric extraction when RGB identity remains reliable. Both benefits are falsifiable and untested. If the same two pieces always co-occur, instance masking/goal ablations and shape-held-out tests must expose accidental context/word memorization. Do not use random row splits, reused frames or two alternative policies to inflate statistical diversity.

## Motion coverage (verbatim API output)

All 16,745 original paired rows are materialized once: A=episode_2026091922002701 has 12 intervals partitioning [0,9015); B=episode_2026091922062101 has 10 partitioning [0,7730). There is no fabricated N+1 record. There are 20 inter-instance handoffs in total. At each handoff, 30 rows on either side are retained but excluded from policy action loss because release-versus-next-approach ownership is not exposure-exact; this removes 1,200 possible action-loss rows, not source records. A further per-row validity rule masks null/nonfinite command dq and failed derived inputs. These are not imputed. The 15,545 rows outside the explicit handoff bands are only a maximum candidate supervision count, not a count of independent demonstrations or successful actions.
Inspected broad third-camera views cover both entire recordings; wrist evidence confirms a long slender rigid pushing tool, outer-edge contacts, inner-hole engagement and re-contact. Motion summaries show large initial descent from approximately base z=0.365 m to approximately 0.05 m, mostly low-height planar travel with elevation/withdrawal variations; these coordinates do not prove a surface/contact height. Inspected commands and measured dq are distinct. B around 4050-4200 contains relatively large joint/posture adjustment while the R instance remains the objective; retain it with uncertainty instead of making an unsupported separate recovery label. Recorded endpoints show an arrangement visually consistent with HI and WORLD viewed sideways, but success/request labels are absent and final stability is not certified.

## Unobserved cases (verbatim API output)

No recordings establish recognition or manipulation of wholly new letter identities/fonts/topologies, distinct repeated-character instances, new friction/materials, arbitrary metric layout precision, crowded/stacked inventory, flips, falling off the table, picking/grasping, robust multi-object collision recovery, or high-level planning success. No verified force/contact/success labels, object masks/poses, word requests or complete robot-controller execution specification are provided. These gaps do not remove the required unseen-shape/word task: the proposed geometry-conditioned and RGB-history alternatives plus the recognition/layout/HLA pipeline explicitly target it and must undergo the independent tests described above. Competence remains untested and likely needs more authorized diverse demonstrations and evaluation assets. One-time human-assisted safety/camera/table/tool commissioning is a disclosed deployment dependency, not per-move human selection. Optional user clarification of an impossible/ambiguous request must be counted separately from autonomous feasible-task success. All present work stops at cuts, supervision contracts and independent prior/policy designs.

## Overlap rationale (verbatim API output)

No materialized source overlap and no concatenation of unrelated endpoints. Both independent policy alternatives reuse the identical dataset group, which is not additional demonstration evidence. Supervised ranges equal materialized ranges, with the explicitly declared 30-row edge bands excluded from action loss; those rows may be causal context inside their own segment or training-only goal-anchor evidence. There is no cross-segment history window. At invocation/segment start reset motor memory and pad missing history with masks, never borrow future rows or the prior segment's hidden state. At deployment a persistent perception tracker may carry only causal scene identity/state; the selected motor policy is reset and warmed from currently available observations. Memory is not transferred between independently trained policies. Stop/goal anchors can be inside supervision exclusions because they label the preceding objective rather than supplying action targets. Within each policy weight repeated command/frame runs by elapsed robot time and balance segment/instance contributions so long L trials and stationary periods do not dominate. Keep an original source sample in one evaluation partition across all reuses, derived crops, masks and priors. Split by episode at minimum; for new-shape evaluation split by physical instance/shape family as well.
