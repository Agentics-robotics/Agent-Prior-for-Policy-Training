## Task interpretation (verbatim API output)

The intended autonomous task is to arrange available physical letters into a user-requested word with an explicit spatial layout, including entirely unseen letter identities and shapes. Authorized evidence comprises only the two supplied Push recordings, 9015 and7730 paired records. Inspected scenes appear to use seven brown flat letter-like cutouts and a long rod mounted on the robot; third and wrist views plus state/actions support planar nonprehensile pushing, turning, clearance moves, repeated contacts and later corrections. An apparent right column resembling WORLD and two other flanged shapes are visual interpretations, not verified targets or endpoint success. Neither episode supplies ground-truth inventory, poses, masks, word, contact or success. The library is therefore defined by geometry-goal responsibilities and physical track IDs. This stage publishes exact indexed cuts and implementable design/label contracts only, not annotations already performed, policy code, training, execution or evidence from other datasets.

## Goal conditioning (verbatim API output)

Shared label protocol G: for each object segment, identify the unique described physical component at its listed in-segment seed row, track it through that materialized sequence, and obtain its achieved footprint at the explicit goal row stated in label_derivation (normally supervised_stop-1). Annotate/audit segmentation masks with holes at these anchors, propagate with forward/backward optical flow for TRAINING LABELS, and record confidence and provenance per row. These annotations do not presently exist. Do not infer the requested word. Use a rigid planar contour registration between the entry reference mask and goal-row mask; retain multiple orientation hypotheses for symmetries, not a PCA sign chosen as semantic upright. In image coordinates store original and undistorted polygons, mask transform, reference frame/camera and uncertainty. If a verified support/top-plane calibration is acquired, project the same polygons into table metres to fit SE(2); otherwise geometry-metric losses are ineligible and the visual alternative uses normalized image masks. Achieved-goal hindsight labels are training-only caller-argument surrogates, not future observation inputs. A goal is fixed for a call; at time t only the current causal track, pose covariance and tool state update the relative error and obstacle map. Never replace a fixed goal with the current object location. Tool handoff protocol E: optional exit_tool_pose is the actual T_base_ee at the segment's final supervised row; this makes demonstrated post-push lateral departure/approach a conditioned action rather than an unexplained next-object motion. It is a tool waypoint, not a claim of zero velocity or stable contact. End-of-object sequences may terminate above or near the next piece, so clearance validity must be checked, not assumed. Online the agent supplies E from a collision-checked next-access plan; if omitted, a verified clearance retract is used and the demonstrated in-contact portion remains the main objective. Access goals similarly use the specified endpoint T_base_ee. The agent can specify layout in calibrated table coordinates only after commissioning, or directly as third-view goal footprints/orientation vectors. For metric layouts it chooses a support-plane origin/basis with upward normal and projects footprints with camera intrinsics/extrinsics. User word alone is insufficient: ask for or propose an explicit baseline origin, reading direction, upright direction, spacing/margins, and layout bounds; test inventory feasibility before movement. Geometry comes from the current pieces, not a memorized font template.

## Portfolio rationale (verbatim API output)

Three reusable subtasks, four independent policies. tool_access exposes high/low approach, clearance and repositioning so the agent need not ask a shape policy to improvise every entry. piece_relocation moves one selected physical piece to a staging or final geometric goal; keeping full recontact cycles avoids turning each teleoperator adjustment into a new letter-specific skill. local_alignment refines a previously staged or nearly placed piece while preserving nearby placements, including repeated micro-corrections and short lifts. Its dataset also reuses late portions of difficult relocations. A boundary-equivariant/response-model prior and a dual-view goal-mask temporal prior are meaningfully different alternatives for relocation: one explicitly shares local geometric dynamics, the other retains appearance and history through partial occlusion. The alignment prior is intentionally local and feedback-heavy, distinct from long open-loop moves. Access has one obstacle/kinematic prior because two episodes do not justify multiple cosmetic navigation models. No one-policy-per-letter, one-policy-per-word, fixed sequence, or single monolithic trajectory-replay model is proposed.

## Model inventory (verbatim API output)

Existing assets: original RGB/depth files, exact numeric arrays/action_json, sample/media hashes and mappings, per-episode camera intrinsics/extrinsics and TCP/teleop metadata. Calibration reports third/wrist 1280x720 RGB, K/distortion, T_base_cam and T_flange_cam, board pose, ~3.23 mm pose consistency and ~4.42 px reprojection RMS. These are not verified object/table-plane truth. Both camera-PC factory wrist intrinsics and a different calibrated wrist K exist: use the K/distortion paired with the selected extrinsics and validate overlay reprojection; never mix them silently. RAW preprocessing P: retain all clocks and original paired indices; decode action_json without altering nulls, validate transform rotations, normalize finite q/dq/tau features with validity masks and training-fold statistics; distinguish measured dq from commanded action.dq. Exclude gripper_position=-1 and NaN width as measurements; no grasp/open-close objective. RGB undistortion and 640x360 full-view tensors plus optional 256x256 original-coordinate target/tool crops are deterministic derived inputs, independent of inspection previews. Wrist extrinsic at row i is T_base_flange(i)*T_flange_cam. Recorded EE already includes TCP xyz[0,0,0.2], rpy[0,0,-90deg]; do not apply twice. Tool CAD/tip radius and true offset, table bounds/height, contact-height limits and robot collision geometry/URDF must be acquired or verified in commissioning. Depth is preserved but unused as a required input until scale, registration, invalid values and accuracy are validated. Perception S: class-agnostic instance segmentation and rod/occlusion segmentation (proposed pretrained segmentation backbone plus task fine-tuning); causal multi-view optical-flow/association tracker; calibrated rigid contour registration with covariance and explicit symmetry hypotheses. Obtain training-only anchor masks/track audits, frozen licensed weights, annotation manifests and quality metrics; these are obligations, not existing labels. Optional table reconstruction uses ray-plane intersection after support plane/letter height calibration, with sensitivity bounds, never filename-derived depth units or board=table assumption. Maintain third-UV representation when metric pose is unavailable. Four learned policies: access phase/residual network; boundary-equivariant proposal network plus contact-response ensemble; independent masked-goal dual-view temporal action model; local contact-mode/response-residual alignment model. They share converters/perception and safety interfaces, not policy weights. Semantic recognizer is a separate pretrained/open-set model needing independent testing; layout/inventory assignment, collision checking and call monitor are deterministic algorithms with learned uncertainty inputs. Action decoder D: train primarily against finite ORIGINAL action.dq seven-joint velocity commands, not observed dq; retain action.v in base and action.w in EE as additional recorded supervision and diagnostic heads. In access/geometry models a task-space proposal plus q-conditioned kinematic/residual decoder learns the command mapping; visual policy predicts joint commands directly. Do not equate J(q)*dq_measured or even J(q)*dq_command to recorded v,w: lead, follower, damping/posture and timing can differ. The proposed differentiable kinematic layer is a soft geometric prior, with an independently audited residual, not an asserted exact inverse of these recordings. Null dq means no joint/action-decoder loss, even when finite v/w can supervise auxiliary intent; null entire commands mean no action loss. Execution emits verified joint_velocity commands in the controller's checked joint order and units (candidate rad/s) at verified 20 Hz hold/timing, with watchdog, velocity/acceleration/jerk, joint-limit, collision and torque-envelope checks. It does not send arbitrary track_twist JSON or target_pose-null as a pose. Frame/timing/units and reproduction of recorded dq from candidate decoder must be tested against recording-controller implementation before robot deployment; translation units candidate m/s, rotation candidate rad/s from metadata require confirmation. Recorded w often zero while tool attitude changes, so force neither perfect fixed orientation nor an unverified exact twist decoder. Decoder clipping triggers diagnostics/replan rather than silently retraining altered labels. Later implementation must ship executable P/S/G/E/D converters, trained/pretrained assets, URDF/tool/plane calibrations, safety monitor, invocation examples and per-behavior eligibility counts alongside all policy implementations.

## Generalization design (verbatim API output)

Separate four axes. (1) Semantic transfer: a proposed open-vocabulary visual-language recognizer returns character hypotheses and upright-direction distributions for each class-agnostic track. It must not use a fixed seven-piece classifier or sticker/barcode lookup. Confidence-calibrated inventory matching allocates distinct physical IDs to repeated requested characters; report unavailable multiplicities, unreadable pieces and infeasible layouts separately from manipulation failure. No such recognizer/weights/labels are supplied; acquire licensed pretrained assets and an independent open-set evaluation/annotation set. Human clarification may resolve semantic ambiguity, but it reduces autonomy and is never an assumed per-move controller. (2) Physical shape transfer: push_boundary_v1 shares local contour/normal/contact-response parameters over arbitrary outer and inner boundaries, with current geometry and online observed response rather than identity embeddings. push_visual_v1 provides an independent dual-view appearance/goal-mask temporal prior when clean contour/pose estimates are difficult. align_local_v1 uses locally updated response estimates and conservative short strokes. These are testable hypotheses, not proof that goal acceptance implies novel-shape competence. Acquire additional rigid pieces including entirely unseen characters, fonts, concavities, thin branches, holes, sizes, mass/friction combinations and clutter; some shapes may be unpushable with this rod and require a detected BLOCKED result rather than fabricated success. (3) Word/layout transfer: agent translates the word and explicit baseline, direction, orientation and spacing request into per-instance footprints using the actual inventory widths, collision margins and reachable workspace; staged moves are permitted and previously placed pieces are protected. It does not condition motor policies on episode identity, inferred recorded word or fixed object order. (4) Arrangement/control transfer: balanced staging/final goals, relative representations, short-horizon feedback, obstacle-aware access and mode memory address different starts and ordering. Evaluate leave-one-episode-out only as a limited same-inventory check; never call it unseen-shape evaluation. New held-out physical-instance/shape splits must exclude the same shape across all fonts/views/tracks as appropriate. Independently test unseen identity with recognizer, unseen physical shapes with oracle semantic IDs, unseen words on feasible known geometry, new layouts/arrangements, and a joint unseen-shape plus unseen-word plus new-arrangement suite. Include duplicate-character allocation, impossible inventory, identity ambiguity, occlusion, camera drift, protected-object disturbance, failed contact, near-edge cases and changing friction. Measure local pose/contour error, orientation ambiguity, completion calibration, contact/retry count, collisions, time, whole-word correctness and coverage after preprocessing. Compare four-policy composition, alternative selection, and ablations of geometry, wrist history, response adaptation and staging. No new-shape or word success is claimed.

## Calling contract (verbatim API output)

Catalog version 1: access_clearance_v1 (tool_access), push_boundary_v1 and push_visual_v1 (piece_relocation), align_local_v1 (local_alignment). These are four independently trained callable policies, not four sequential stages. The High-level Agent owns request interpretation, physical-instance assignment, explicit layout generation, choice of staging versus final goals, call order, retries and whole-word verification. Common call: policy_id, call_id, scene_track_version, instance_id where relevant, goal, protected_instance_ids, optional exit_tool_pose, tolerances, time_budget, safety_profile. An instance_id is a tracked physical component, not a character class. A goal is a fixed desired footprint with holes and an orientation cue in third_undistorted_uv (original image coordinates normalized by 1280,720), optionally accompanied by a verified table-frame SE(2) pose in metres/radians. A tool goal is T_base_ee in metres and rotation matrix; it refers to the recorded EE/TCP convention, not a newly assumed tip. Policies consume causal paired RGB/state history and output proposed seven-joint velocity commands plus diagnostics, through the common verified decoder described in model_inventory. Report RUNNING, LOCAL_GOAL_REACHED, NEED_REPOSITION, BLOCKED, LOST_TRACK, UNCERTAIN or SAFETY_STOP, with translation/contour/orientation residuals, protected-object displacement, track covariance, contact-mode probabilities, elapsed time and decoder clipping. LOCAL_GOAL_REACHED is not word success. Entry checks reject stale IDs, impossible geometry or unsafe goals. Completion requires current observed geometric agreement sustained across at least five valid observations and appropriate tool clearance; tolerances are caller supplied but must exceed perception/calibration uncertainty. Endpoints here are relabelled achieved local goals, never verified task successes. Representative A sequence: access zigzag piece, relocate it, stage central flanged piece, relocate ring, stage R-like piece, restage flanged piece, relocate upper H-like piece, stage D-like piece, return R-like piece to right column, align D-like piece, relocate/recontact L-like piece, align the two flanged pieces. Representative B differs: zigzag, flanged staging, D-like staging, ring, R-like repeated attempts, D-like correction, L-like relocation, H-like relocation, flanged correction, H-like revisit. Calls use the actual tracked instances and observed slot goals; these are examples, not a hardcoded spelling/order. A new request may require repeated access/relocate/align calls in any feasible order. On failure, first stop, reassess geometry and inventory, then choose another policy, a reachable intermediate goal, or request semantic clarification; do not silently enlist a human to choose each push.

## Sharing and diversity audit (verbatim API output)

There are 28 materialized sequences: 4 access, 16 relocation, 8 alignment; two relocation policies share the same 16-sequence dataset but are trained independently. Identity aliases W/O/R/D/L/H/I describe inspected shape/position only; seven apparent physical pieces per scene is a visual inference and cross-episode physical identity is not certified. Perception, coordinate conversion, semantic matching, layout and safety components are shared for interface consistency. Policy parameters and response heads are separate; alternative gains must be evaluated with the same splits and caller goals. Windows are constructed within one materialized source segment only. At a supervised row use up to the preceding 15 rows and current row, actual t deltas and validity masks, never rows before segment start; left-pad missing history with a mask, not invented observations. Short action chunks have at most 0.2 s horizon and losses only on rows in the supervised interval with the relevant command present; time-query models are trained on original irregular timestamps and queried online at verified control cadence, without re-pairing devices. Reset policy hidden state on a new instance/goal/call; initialize from current causal history, transferring tracker IDs/covariance but not hidden future-goal state. Repeated constant commands are weighted by source robot elapsed duration rather than treated as independent 30 Hz control decisions; preserve 20 Hz teleop versus 30 Hz recording distinction. Balance sequences and behavior modes; cap contribution of long idle holds without deleting them. Weight duplicated (trajectory,index,component-loss) uses inversely by multiplicity within shared-component training; for independent policies count reuse explicitly instead of pretending extra independent data. Group every cut/overlap/anchor from an episode together in train/evaluation; no random-frame split. Hindsight goal sampling is restricted to inspected/reliably annotated achieved subgoals within the same physical-instance sequence, with its horizon/provenance recorded. Whole-episode held-out checks remain small-data diagnostics, not novel-letter validation. Eligibility gate: every behavior above must retain action supervision in at least one applicable policy after preprocessing, or acquire missing annotations/data and report the gap before training is accepted.

## Unobserved cases (verbatim API output)

The task requires new semantic letters, entirely unseen physical shapes, new words and layouts; these remain core evaluation/acquisition obligations, not silently excluded deployment requirements. No success on these dimensions is established by two same-looking inventories. Missing assets include open-set semantic recognition and uncertainty calibration, audited instance masks/tracks and achieved-goal labels, accurate support/top-plane/tool geometry, verified depth conversion if used, robot controller unit/timing/decoding contract, and diverse new-shape interaction data. Unobserved or weakly supported capabilities: impossible/ambiguous request handling, repeated identical-character inventory, automatic layout feasibility and semantic upright resolution, very crowded/stacked pieces, deformable or tiny letters, boundary/edge recovery, rod entrapment, major accidental neighbor displacement, tactile force control, tool changes, camera calibration drift, arbitrary occlusion/search and recovery after a fall. Proposed policies must detect and report unsupported/unsafe conditions while maintaining the intended generalization workstream; do not relabel unsupported cases as demonstrated success. All original source media/calibration/hashes/missingness remain preserved, no cross-clock sample shifting or fabricated terminal record is allowed, and later authorized implementation must audit actual per-behavior training eligibility before claiming full coverage.

## Overlap rationale (verbatim API output)

Each main segment includes 15 original rows (~0.5 s) of preceding/following context where available; initial sequences start at 0 and terminal sequences end at N. This provides pre-entry tracking, causal short history, and observed handoff evidence, not extra action supervision under the wrong object's goal. Supervised ranges include their own approach, recontact, push, release and conditioned E departure. Context from a preceding object never receives a loss for the current object. Following context can provide training-only stopping/label audit but cannot enter an earlier observation window. Deliberate cross-group action overlap: A[6150,6340) and B[2750,2940) teach tool-only navigation with endpoint tool goals; in parent object groups their release/access motions are conditioned on that group's object goal plus E. A[7800,8130) and B[4050,4710) teach both full-goal continuation and a separate near-goal/recontact alignment call with identical achieved geometric goal provenance. Overlap is not an independent episode or proof of more shape diversity. If an access interval is found to move an object on dense annotation, its contact portion must be reassigned to the appropriate object group rather than labelled collision-free. Boundary samples are chosen within release/approach corridors, not as force-verified contact events.
